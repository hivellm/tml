## Bottleneck Analysis

1. **Debug build (O0)**: All code unoptimized. Release build expected 2-4x improvement.
2. **Syscall overhead**: 2 syscalls per request (recv + send) at ~50μs each = ~100μs floor.
3. **Mutex queue**: Accept thread contends with workers on shared queue lock.
4. **No vectored I/O**: Each send is a separate syscall.

## Key Finding: Syscall-Bound

Release (O3) confirmed at 181K — identical to debug. **Server is syscall-bound, not CPU-bound.** The 2 syscalls per request (recv+send at ~5μs each) define the throughput ceiling.

## Profiler Intrinsics (Zero-Cost)

Profiler calls are compiler intrinsics — emit `add i64 0, 0` (1 instruction) instead of function calls. With 70+ zones active: 159K req/s (13% overhead). Without: 183K.

## Path to 500K

1. **True HTTP pipelining** — N requests per recv, N responses per send (server code exists, needs wrk/h2load client)
2. **io_uring (Linux)** — batched I/O submission
3. **Fix IOCP mode** — currently 13K, should be 200K+
4. **Reduce syscall count** — combine header+body into single send
