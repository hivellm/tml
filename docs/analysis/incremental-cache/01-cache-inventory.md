# 01 — Cache Inventory

Every cache layer found, with key scheme, granularity, and invalidation trigger. Paths relative to repo root.

|---|---|---|---|---|---|---|---|
| 1 | **Query in-memory cache** | per-`QueryContext` RAM (`compiler/src/query/query_cache.cpp`) | `QueryKey` variant (file_path, module_name, +codegen opts) | per query (9 kinds) | end of process; `invalidate_dependents` (unused in practice) | n/a | one context per compiled file → near-zero cross-file sharing |

| 11 | **Runtime deps cache** | `build/debug/cache/tests/deps/`, `tml_test_runtime.lib` archive (`testing_compile.cpp:169-179`) | filename existence | per C-runtime obj / archive | manual delete; archive rebuild timestamps feed layer 5's hash | none | works; mtime feeds over-invalidation |
| 12 | **C++ compiler build** | `build/cache/<triple>/<config>/` (ninja) | ninja timestamp graph; zig cc, **no ccache/sccache** (`scripts/build.bat:240-334`) | per TU | timestamps | ninja | relink → new DLL mtime → cascades into layers 2, 5, 8 |
| 13 | **Daemon-resident meta** | `GlobalModuleCache` singleton inside daemon process | module path, filled once via `std::call_once` (`module_binary_read.cpp:1376-1379`) | per module | **never re-validated during daemon lifetime** | daemon restart | correctness hole (F-029) |

Cross-layer invalidation cascade on every `scripts\build.bat` run that relinks `tml_compiler.dll`:
new DLL mtime ⇒ (2) incr.bin fully red ⇒ (5) all suite EXEs invalidated ⇒ (8) daemon self-terminates —
even when the rebuild changed nothing behavior-relevant. Contrast: sccache/ccache key on *content*, rustc keys
its dep-graph on crate metadata hash, Bazel on action content keys.
