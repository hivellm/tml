# v0.3.58 — Sound Container Read-Outs + Destroy Releases (phase26b Step 3)

**Date:** 2026-07-16 · **Branch:** `fix/era0-stabilization` · **ERA 0, Phase B (B1-on-AST)**

Closes the concrete double-free/UAF (F-016) and container-leak (F-022) bug classes
from the memory-copy audit at the LIBRARY level — no compiler change, no move
semantics required (that milestone is phase26f).

## F-016 — read-outs become balanced clones (were bitwise aliases)

Every by-value yield out of an owning container/smart pointer now goes through the
`ptr_read_clone[T]` intrinsic (deep-clone when `T` carries refcounted handles,
identity for primitives) — the same fix `List/HashMap::get` received in phase24n:

- `ListIter::next`, `HashSetIter::next` (`behaviors.tml`), `HashSetIter::current`/
  `next_item` (`class_collections.tml`), `HashMapIter::value` (`hashmap.tml` — `get`
  was fixed in 0.3.52, the iterator had been missed).
- `Sync::get` and `Heap::get` (with `Heap::duplicate` simplified accordingly — its
  old `this.get().duplicate()` double-cloned through a dropping temp).
- `List::retain` rebuilt precisely instead of blanket-cloned: the predicate now
  BORROWS the slot (`ref (*elem_ptr)`), kept elements that shift move byte-wise via
  `mem_copy` (no typed local → no spurious drop-glue), and only REMOVED elements are
  read into an owning local — whose drop, exactly once, releases them. Keeping an
  element no longer bleeds its refcount.
- `Arc::make_mut` CoW deep-clones via `T::duplicate` (new `where T: Duplicate`
  bound — the honest CoW requirement); old+new inners no longer alias nested handles.

## F-022 — destroy releases element handles (was: leak everything)

- `List::destroy` drops each live element (`0..len`) before freeing the buffer.
- `HashMap::destroy` drops the key and value of every occupied slot (ctrl ≥ 0)
  before freeing the arrays.
No-op for primitive element types.
