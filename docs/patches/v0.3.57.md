# v0.3.57 — Borrow Ownership Facts Exported + Def-Span Join Proven (phase26b Step 2.1-2.3)

**Date:** 2026-07-16 · **Branch:** `fix/era0-stabilization` · **ERA 0 Stabilization, Phase B**

Foundation plumbing for the ADR-009 B1-on-AST memory-model fix. The NLL borrow
checker computes precise per-place ownership state and historically discarded it
(`provide_borrowcheck_module` returned only success+errors). This release exports
those facts, plumbs them into the AST codegen, and **proves the join key** the
eventual drop-suppression swap (Step 2.4) will rely on. **No drop behavior
changes** — facts are computed and (behind a debug flag) logged, never yet
consumed. Zero functional change to emitted IR.

## Changes

- **Export (2.1):** new `PlaceOwnershipFact { def_span, name, moved_out, initialized }`
  (`compiler/include/common.hpp`) and a `std::vector<PlaceOwnershipFact> ownership`
  field on `BorrowcheckResult` (`query_key.hpp`). `BorrowChecker::ownership_facts()`
  snapshots `env_.all_places()` — `OwnershipState::Moved -> moved_out`,
  `is_initialized -> initialized` — keyed by each place's definition `SourceSpan`.
  Populated in `provide_borrowcheck_module` before the stack-local checker dies.
- **Plumb (2.2):** `LLVMIRGen::set_ownership_facts()` stores facts into
  `ownership_by_span_` (keyed by packed start/end byte offsets). Wired at the
  query codegen-unit site (`query_core.cpp`) and the direct-CLI construction
  sites (`build.cpp`, `parallel_build.cpp`, `run_profiled.cpp`) so both `tml build`
  and `tml run` (AST path) receive facts. `llvm_codegen_backend.cpp::compile_ast`
  is left unchanged — it has no borrow-result source and no live callers.
- **Carry the key (2.3):** `DropInfo` gains a `def_span`; `register_for_drop` takes
  an optional `def_span` and the 8 `gen_let_stmt` call sites + the const-decl site
  thread `let.span` / `const_decl.span`.
- **Join proof (debug scaffolding):** behind `TML_DROP_FACTS_DEBUG=1`,
  `emit_scope_drops`/`emit_all_drops` log per-binding whether the drop finds its
  ownership fact by def-span (MATCH/MISS) and whether the fact's `moved_out`
  agrees with `consumed_vars_`. This does NOT change the drop decision; it is the
  basis for Step 2.4.

## Join-proof result

- **Def-span join is CONFIRMED VIABLE.** 100% of drop-registered user-module
  `let` bindings that carry a span matched their exported fact (refcount canary
  5/5, explicit-move probe 3/3; **0 MISS-no-fact**). Both phases read the same
  cached parsed module, so `let.span` byte offsets are identical — distinguishing
  shadowed names a bare-name key cannot. The only misses are synthesized
  library-internal bindings with no `let.span` (correctly classified MISS-no-span).
- **Decision-critical for Step 2.4:** `moved_out` is currently **uniformly false**.
  `BorrowChecker::move_value()` — the only writer of `OwnershipState::Moved` — is
  dead code (declared, defined, never called), and the partial-move path
  (`move_projection`/`moved_projections`) does not fire for function-arg or
  let-init moves either. Confirmed: `let y = x; use_it(x)` (blatant use-after-move)
  compiles clean with no B-error. So the checker's move dataflow is dormant
  (consistent with the repo's F-015 "no move semantics is systemic" audit).
  Step 2.4 must first activate the checker's move dataflow at move sites before
  suppressing drops on `moved_out`; otherwise `moved_out`-based suppression would
  suppress nothing and be strictly worse than the current `consumed_vars_`.
  `initialized` is accurate and immediately usable.

- `core/alloc` 44/44. `compiler/compiler` 21/22 — the one miss is a `cc_driver`
