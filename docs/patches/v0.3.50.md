# v0.3.50 — Function-like macros + GCC `, ##__VA_ARGS__` comma-elision (phase24i)

**Date**: 2026-05-03
**Branch**: feat/self-hosting-compiler
**Task**: phase24i_cc-variadic-macro-paste
**Predecessor**: v0.3.49 (phase0z residual, pointer-returning function definitions)

## Summary

`cc_driver` rejected every `#define` that takes parameters. The
phase24i task originally targeted only the `, ##__VA_ARGS__` GCC
extension that fires inside `compiler/runtime/diagnostics/log.h:216`,
but the bisect uncovered that **function-like macros were not
implemented at all** — even non-variadic `#define M(x) f(x)` failed.

Pre-phase24i `pp_handle_directive::define` always called
`pp_define_object`. For `#define M(x) f(x)`:

1. `drop_first_ident(body)` strips the `M` identifier, leaving
   `(`, `x`, `)`, ` `, `f`, `(`, `x`, `)`.
2. `pp_define_object` registered `M` with that entire token sequence
   as the body.
3. At call site `M(1)`, `expand_object_macro_into` replaced the
   identifier `M` with the body verbatim, producing
   `(`, `x`, `)`, ` `, `f`, `(`, `x`, `)`, `(`, `1`, `)`.
4. The C parser saw `(x) f(x) (1)` and rejected it.

## Phase 1 — Bisect

the fix; all pass after.

## Root cause

Two interacting bugs:

1. **Function-like macro support missing.** `pp_handle_directive`
   only routed `#define` through `pp_define_object`; the
   `MacroDef::FunctionLike` enum existed but was never written to,
   and the call-site expansion path (`expand_object_macro_into`)
   only knew object-like substitution.

2. **Heap-borrow-drop on nested `List[List[PpToken]]`.** A first-cut
   implementation used `args: List[List[PpToken]]` for the
   collected argument lists. Across 10 runs, ~7/10 succeeded and
   ~3/10 produced garbage tokens (parse errors with non-deterministic
   column positions). This is the same Heap-borrow-drop pattern
   documented in the archived phase24g proposal: nested `List[T]`
   allocations share inner buffers via the still-unique `Heap[T]`
   and randomly drop them. The fix sidesteps the nested-List hazard
   entirely by storing all argument tokens in a single flat
   `List[PpToken]` plus an offset table — equivalent to a CSR layout.

## Fix

`compiler-tml/src/cc/preproc/macros.tml` (+~410 lines):

- `pub func dup_pp_token(t: PpToken) -> PpToken` — deep-clones
  `text`/`file` Str fields. Used at every site that pushes a
  macro-body or argument token into a longer-lived container.
- `pub type ParsedFuncMacro { params, is_variadic, body }` plus
  `is_function_like_define`/`parse_func_macro_def` — detect the
  function-like form (the very first token after the macro name is
  `(` with no whitespace) and parse the parameter list.
- `pub type CollectedArgs { flat, offsets, end }` plus
  `ca_arg_count`/`ca_arg_len`/`ca_arg_token`/`ca_arg_is_empty` —
  flat-storage replacement for `List[List[PpToken]]`.
- `pub func collect_macro_args` — walks tokens from the opening `(`,
  tracks paren depth (so commas inside nested `(...)` don't split
  arguments), and packs every arg token into `flat` with offsets.
- `pub func substitute_func_macro` — implements parameter
  substitution, `__VA_ARGS__`, the GCC `, ##__VA_ARGS__`
  comma-elision extension (drop the comma when VA is empty,
  preserve it when non-empty), and plain `##` token pasting
  (C17 §6.10.3.3).

`compiler-tml/src/cc/preproc/directives.tml`:

- `pp_handle_directive::define` now detects function-like macros
  and routes through `parse_func_macro_def` + `pp_define_function`.
- `expand_object_macro_into` becomes `expand_macro_at` — handles
  both `MacroDef::ObjectLike` (substitute body verbatim) and
  `MacroDef::FunctionLike` (look ahead for `(`, collect args,
  substitute). Returns the number of input tokens consumed so the
  caller can advance past the trailing `(...)` invocation.
- `strip_ws` now deep-clones via `dup_pp_token` so the returned
  list survives the caller's transient token buffer drop.
- The fall-through `out.push(tok)` in `pp_sweep_in_file` deep-clones
  too so the swept stream is independent of `raw_pp`.

`compiler-tml/src/cc/preproc/token.tml`:

- `pub func pp_define_function(pp, name, params, is_variadic, body)`
  — analogue of `pp_define_object` for the new `FunctionLike` form.

`compiler-tml/src/cc/preproc/tokenize.tml`:

- Punctuator scanner recognises `##` as a 2-char token. Without
  this, a `##` in source produced two adjacent `#` Punct tokens and
  the macro substitutor never saw the paste operator.

## Follow-ups

- `essential.c` self-compile still gated on the
  `Maybe[Heap[CBlockItem]]` cleanup SIGSEGV. Same Heap-borrow-drop
  bug class; needs the structural phase24g (refcounted `Heap[T]`)
  fix.
- The phase24i `, ##__VA_ARGS__` implementation only handles the
  most common GCC-extension shape. The full C23 `__VA_OPT__(...)`
  is out of scope for this patch; tracked separately if needed.
- Macro re-scan (recursive expansion of expansion results) and
  the blue-paint algorithm in `expand_macros` are not used by the
  new `expand_macro_at` path. Self-referential macros are
  protected only by the lookahead check (a macro that expands to
  its own name with the same call shape would loop). Tracked as
  follow-up if any real-world C input hits this.
