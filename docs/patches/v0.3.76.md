# v0.3.76 — Shared-stdlib fast-path: two codegen blockers fixed, enablement still gated (phase43a, F-006/F-007)

**Date:** 2026-07-18

## Summary

phase43a targets the biggest remaining tooling-performance lever (F-006/F-007): the
disabled `build_stdlib_object` fast-path that would emit the stdlib **once** instead of
re-emitting ~5000 functions / 287 modules per test file. phase41b root-caused four blockers.
This release **lands the two clean, independently-safe codegen sub-fixes** (blockers 1 and 2)
that fix K001 roots regardless of the fast-path, and keeps the fast-path **OFF** because the
remaining two blockers (range-iter width + the scoped-bootstrap / decls-only-linking redesign)
cannot yet pass the zero-divergence gate. This is the sanctioned 1.8 fallback: honest partial
progress with each landed sub-fix independently gated, no regressing enable forced.

## Landed (codegen sub-fixes — safe with the fast-path off)

**Blocker 1 (FIXED) — generic MODULE FREE FUNCTION monomorphization.**
A library-body call to a generic free function (concretely `core::runtime::mem::replace[T]`,
`lib/core/src/runtime/mem.tml`) was emitted as the UN-monomorphized template symbol
`@...mem7replaceE_R1T1T` (literal `T`) with no matching define → "use of undefined value".
Root: generic module free-function calls had **no** call-site re-mangle+queue branch, whereas
generic `Type::method` calls do; when `gen_call_generic_func` misses (its `pending_generic_funcs_`
lookup fails under a partial/restored bootstrap) the call fell to the declaration-name fallback
in `call_user.cpp` and queued nothing. **Fix (`call_user.cpp`):** after `free_func_type_subs`
is built, when the callee is a module free function whose `func_sig->type_params` is non-empty
AND **all** resolve to concrete types, re-mangle to the monomorphized symbol via
`require_func_instantiation(bare, type_args)` and override the callee — the call and the
drained define share `mangle_func_name` so the names match by construction. Guarded strictly
on all-concrete; fires only on the `gen_call_generic_func` miss path (the dangling-ref
territory), so it is inert on the passing generic-call path. This is **distinct** from
phase27e's bare-name collision fix (that was the reproducible slow-path `core/str` case; this
is the genuinely-generic case, only reachable under the fast-path).

**Blocker 2 (FIXED) — dedup keyspace.**
`CodegenLibraryState` captured only `generated_functions_`, leaving the two impl-method dedup
sets empty in every restored worker, so the emission guard `generated_impl_methods_output_.count(...)`
was blind to what the cached library already instantiated → `I32::duplicate` redefinition.
**Fix:** `CodegenLibraryState` now captures **and** restores both `generated_impl_methods_`
(REQUEST dedup) and `generated_impl_methods_output_` (EMISSION dedup)
(`llvm_ir_gen.hpp`, `generate_support.cpp`, `generate.cpp`).

## Remaining (fast-path stays OFF — documented residual)

**Blocker 3 — range-iterator i64/i32 width (K001 Class 2).** A LOCAL `Range` value/iterator
re-inferred as `Range__I32` vs the cached library's `Range__I64` → width mismatch at the
restore boundary. Only reproducible under the fast-path (each test embeds its own stdlib
today, so there is no cross-boundary mismatch). Needs the index width resolved from the
registered signature, not the i32 `last_expr_type_` default. `loop.cpp` already promotes
direct `for i in 0 to n` bounds to i64; the residual is the Range-as-value / iterator-method
path, whose exact site requires a fast-path reproduction to pinpoint (not guess-edited).

**Blocker 4 — bootstrap + linking redesign.** The monolithic `test_bootstrap.tml` imports
~12 phantom `pub mod` modules (no source file) so its typecheck aborts, and an eager
all-stdlib object times out (>500 s). Enablement needs a per-suite-scoped bootstrap (compile
only the suite's transitive module set — which also dodges the phase27d `mut ref I64`-broken
`std/http` that no core suite imports) plus the F-007 decls-only / external-linkage
shared-object linking.
