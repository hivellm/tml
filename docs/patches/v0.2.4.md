# TML v0.2.4 — 2026-03-25

## Summary

Developer tooling and research infrastructure release: the `--debug-layers` flag exposes HIR, MIR, and LLVM IR on test failure to dramatically shorten the debugging loop, the MCP call logger provides NDJSON telemetry for LLM tool-use research, and diagnosis hints automatically identify which compilation layer likely contains a bug.

---

## Added

### Compiler — Debug Tooling

- **`--debug-layers` flag for `tml test`** — On any test failure, automatically emits the HIR, MIR, and LLVM IR for the failing test functions alongside the error message. Eliminates the need to manually run `tml emit-ir` and cross-reference output when debugging codegen failures.

- **`--emit-hir` flag for `tml build`** — Emits the High-level IR (HIR) to a `.hir` file alongside the object output. Useful for verifying that desugaring, monomorphization, and type resolution produced the expected intermediate representation.

- **`MIR print_function_by_name`** convenience function — Extract and pretty-print a single MIR function by name without printing the entire module. Used internally by `--debug-layers`.

- **Diagnosis hints** — `generate_diagnosis_hints()` analyzes the error message and IR content to suggest which compilation layer (parser, type system, HIR builder, codegen, runtime) is the likely source of a bug. Hints are printed below the IR output in debug-layers mode.

### MCP Infrastructure

- **MCP call logger** — All MCP tool invocations are logged in NDJSON format to `mcp-call-log.jsonl`. Each entry records: tool name, parameters (without output content), timestamp, duration, session ID, and experiment condition. Implemented using C `FILE*` for Windows compatibility (avoids C++ stream issues with concurrent writes).

- **`debug_layers` parameter on MCP `test` tool** — Enables `--debug-layers` mode directly from MCP clients without needing to modify CLI invocations.

- **`TML_DEBUG_LAYERS=1` env var** — Toggles debug-layers as the default in the MCP test tool, enabling A/B experiment conditions (baseline vs. debug-layers always on) without code changes.

- **`TML_MCP_LOG_DIR` env var** — Override the directory where `mcp-call-log.jsonl` is written. Useful for routing logs to a shared location in team or research setups.

### Documentation

- **`docs/user/ch13-04-debug-layers.md`** — User guide explaining the debug-layers feature, what each layer shows, and how to interpret the diagnosis hints.

- **`docs/papers/llm-ir-debugging/`** — Research paper structure for studying LLM-assisted debugging through multi-layer IR exposure. Includes introduction, methodology, experimental design, and results sections.

- **`docs/papers/llm-ir-debugging/scripts/analyze_logs.py`** — Analysis script for the MCP call log. Features: session labeling, A/B condition comparison, Welch's t-test, Cohen's d effect size, and tool transition heatmaps showing which tools LLMs use after a failure.
