# v0.3.3 — K001 `core::str` Method Codegen Fix (AST Path)

**Date**: 2026-04-14

## Highlights

- **K001 fix**: `core::str` free functions (`len`, `is_empty`, `starts_with`, `ends_with`,
  `contains`, `trim`) now emit valid LLVM IR definitions in the AST codegen path
- **String benchmarks unblocked**: `string_bench.tml` and `text_bench.tml` compile and run

## Fixed

### Codegen — AST Path (`core::str` free functions)

When a TML file imports a module that triggers the AST codegen path (e.g. `use std::text::Text`,
or any file with generic functions), the `impl Str` method bodies delegate to free functions in
`core::str::basic`, `core::str::search`, and `core::str::transform`. These free functions were
not registered in `pending_library_funcs_` for the AST path because:

- `core::str::basic/search/transform` are not stored in `GlobalModuleCache` (no `.tml.meta`
  binary disk cache exists for them)
- The `essential_library_modules` auto-registration loop requires one of these two sources —
  without them, registration silently fails

**Fix**: Added 6 inline IR catalog entries to `compiler/src/codegen/llvm/core/runtime.cpp`.
The verify-and-recover loop (lines 477–638 of `runtime_modules_library.cpp`) scans the final IR
for unresolved `@tml_*` references and looks them up in the runtime catalog. These entries are
now found and emitted:

| Symbol | Function | Implementation |
|--------|----------|----------------|
| `tml_N4core3str5basic3lenE_S` | `core::str::basic::len` | `strlen` with null guard |
| `tml_N4core3str5basic8is_emptyE_S` | `core::str::basic::is_empty` | `len == 0` |
| `tml_N4core3str6search11starts_withE_SS` | `core::str::search::starts_with` | `memcmp` prefix check |
| `tml_N4core3str6search9ends_withE_SS` | `core::str::search::ends_with` | `memcmp` suffix at offset |
| `tml_N4core3str6search8containsE_SS` | `core::str::search::contains` | scalar scan with `memcmp` |
| `tml_N4core3str9transform4trimE_S` | `core::str::transform::trim` | forward/backward scan + `mem_alloc` |

All implementations mirror the logic in `lib/core/src/str/` and depend only on already-cataloged
symbols: `strlen`, `memcmp`, `mem_alloc`, `llvm.memcpy.p0.p0.i64`.
