# v0.3.44 — phase24f (partial): declarator_name_heap Heap-borrow-drop

**Date**: 2026-05-02
**Branch**: `feat/self-hosting-compiler`
**Task**: phase24f items 2.x + 3.1

## Summary

`compiler-tml/src/cc/parser.tml::declarator_name_heap(d: Heap[CDeclarator])`
was the same Heap-borrow-drop pattern fixed in phase24c/24d/24e:
the local `Heap[CDeclarator]` parameter shares its allocation with
the caller's Heap (e.g. `Pointer(inner: Heap[CDeclarator], ...)`'s
inner field). The default Drop on the parameter's Heap calls
`mem_free(this.ptr)`, freeing the caller's allocation; subsequent
reads of the caller's Heap chain hit dangling pointers.

Replaced the recursive
`declarator_name → declarator_name_heap → declarator_name` loop
with `declarator_name_value_leak`, which uses `into_raw()` at every
Heap layer to suppress drop on the local copy:

```tml
func declarator_name_heap(d: Heap[CDeclarator]) -> Str {
    var local: Heap[CDeclarator] = d
    let val: CDeclarator = local.get()
    let _raw: *CDeclarator = local.into_raw()
    return declarator_name_value_leak(val)
}

func declarator_name_value_leak(d: CDeclarator) -> Str {
    when d {
        Ident(name) => return name.duplicate(),
        Abstract => return "",
        Pointer(inner, _) => {
            var local: Heap[CDeclarator] = inner
            let nested: CDeclarator = local.get()
            let _raw: *CDeclarator = local.into_raw()
            return declarator_name_value_leak(nested)
        },
        Array(inner, _) => { /* same shape */ },
        Func(part) => { /* same shape with part.inner */ }
    }
}
```

Effect: `declarator_name(decl)` for `(*sig_t)(int)` now correctly
walks `Func(part) → Pointer(inner, _) → Ident("sig_t")` and returns
`"sig_t"` without freeing the caller's CDeclarator spine.

## Coverage

cc_driver runs of `typedef void (*sig_t)(int);` are 60% deterministic
post-fix vs 0% pre-fix (3 out of 5 consecutive runs print
`cc_driver: parsed`, 2 still crash at exit 127/139). The remaining
crashes come from additional Heap-borrow-drop sites in
`cp_parse_top_decl`'s declarator → CTypedefDef move path
(`let td: CTypedefDef = CTypedefDef { declarator: dp.decl, ... }`
copies the CDeclarator value with shared nested Heap pointers, and
both dp.decl + td.declarator try to drop them).

## Open: full deterministic fix needs structural Heap[T]

Surgical `into_raw()` patches at every navigation site is fragile
and error-prone. The structural fix is one of:

(a) Refcounted `Heap[T]` — `mem_free` gated by `refcount == 0`.
(b) Distinguish owning `Heap[T]` from non-owning `Borrow[T]` at
    the language level.
(c) Force deep-clone (Duplicate) on every Heap-bearing struct
    field assignment — high ergonomic cost but no runtime hazard.

Option (a) is the cleanest semantic upgrade. Tracked as a
language-level proposal for after the cc_driver bring-up.
