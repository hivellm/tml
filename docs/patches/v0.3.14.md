## Summary

The plugin loader (`compiler/src/plugin/loader.cpp`) gains two performance
improvements:

1. **Process-level DLL handle cache** — `g_dll_cache` is a static
   `unordered_map` keyed by canonical DLL path. After the first
   `LoadLibraryW` succeeds, subsequent `dl_open()` calls for the same path
   return the cached handle in O(1) with no OS call. Stale entries are
   evicted automatically when the file's `mtime` changes (rebuild
   detection), so tests run after a compiler rebuild always load the new DLL.

2. **Background preload** — `Loader::preload_async({"tml_compiler"})` is
   called in `main_launcher.cpp` immediately after the help/version check.
   A detached `std::thread` starts `LoadLibraryW` in the background.
   `Loader::Loader()` calls `wait_preload_done()` which spins until the
   thread completes, so by the time `loader.load("tml_compiler")` executes,
   the DLL is already in `g_dll_cache` — the explicit load is a cache hit.

3. **Segfault fix** — `unload_all()` now evicts the cache entry and calls
   `platform_dl_close()` (bypassing the "skip if cached" check). This
   ensures `DllMain(DLL_PROCESS_DETACH)` fires during controlled teardown
   rather than at `ExitProcess`, eliminating the static-destructor ordering
   crash caused by LLVM's global registries being destroyed in the wrong
   order when the DLL was unloaded by the OS.

## Implementation

### New static globals (`loader.cpp`)

```cpp
struct DllCacheEntry {
    void* handle = nullptr;
    fs::file_time_type mtime;
};

static std::mutex g_dll_cache_mutex;
static std::unordered_map<std::string, DllCacheEntry> g_dll_cache;
static std::atomic<int> g_preload_count{0};
```

### `dl_open()` — cache-aware

```cpp
auto Loader::dl_open(const fs::path& path) -> void* {
    std::string key = path.string();
    fs::file_time_type current_mtime = get_path_mtime(path);
    {
        std::lock_guard lock(g_dll_cache_mutex);
        auto it = g_dll_cache.find(key);
        if (it != g_dll_cache.end()) {
            if (it->second.mtime == current_mtime)
                return it->second.handle;          // O(1) — no OS call
            platform_dl_close(it->second.handle);  // stale — evict
            g_dll_cache.erase(it);
        }
    }
    void* handle = platform_dl_open(path);
    if (handle) {
        std::lock_guard lock(g_dll_cache_mutex);
        auto [it, inserted] = g_dll_cache.emplace(key, DllCacheEntry{handle, current_mtime});
        if (!inserted) { platform_dl_close(handle); return it->second.handle; }
    }
    return handle;
}
```

### `dl_close()` — skip FreeLibrary for cached handles

During normal `load()`/`unload()` cycles within a multi-load session, cached
handles are not released (keeps the DLL mapped). `unload_all()` is the
exception — it explicitly evicts from the cache and calls `platform_dl_close`
to trigger controlled DLL detach.

### `Loader::preload_async()` / `wait_preload_done()` (`loader.hpp`)

```cpp
static void preload_async(const std::vector<std::string>& plugin_names);
static void wait_preload_done();
```

`preload_async` spawns a detached thread per unresolved plugin.
`wait_preload_done` spins on `g_preload_count` (500µs sleep per iteration).

### Entry point (`main_launcher.cpp`)

```cpp
// After help/version check — preload only when we need the DLL.
tml::plugin::Loader::preload_async({"tml_compiler"});
tml::plugin::Loader loader;          // constructor calls wait_preload_done()
loader.load("tml_compiler");         // cache hit — no OS call
```

## Performance Note

In the debug build, `tml_compiler.dll` is ~78 MB with statically linked LLVM.
LLVM's own static initializers (~2700ms at cold start) dominate over the DLL
I/O cost. The warm-cache O(1) path is measurable (~0ms for the load call) but
the benchmark gate (<20ms warm) is only achievable in a release build or with
a persistent daemon (phase0n). This task implements the architectural
foundation that phase0n will build on.
