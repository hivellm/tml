# v0.3.23 — Fix i128 Binary Operations in Codegen

**Date:** 2026-04-15
**Branch:** feat/self-hosting-compiler

## Summary

Fixes a codegen bug where all U128/I128 binary operations (`==`, `!=`, `<`,
`>`, `+`, `-`, `*`, `/`, `%`) emitted `i32` LLVM instructions instead of
`i128`. This caused K001 compilation failures for any code using 128-bit
integer arithmetic, including the new `U128::to_string()` and `std::msgpack`.

## Root Cause

`compiler/src/codegen/llvm/expr/binary_ops.cpp` line ~690 — the `int_type`
determination ladder had checks for `i1`, `i64`, `i16`, `i8` but **no check
for `i128`**. When both operands were `i128`, none of the conditions matched
and `int_type` defaulted to `"i32"`.

## Fix

Added `i128` check before the `i64` check:

```cpp
} else if (left_type == "i128" || right_type == "i128") {
    int_type = "i128";
} else if (left_type == "i64" || right_type == "i64") {
```

## Impact

- `U128::to_string()` and `I128::to_string()` now work at runtime
- `std::msgpack` writer/reader tests pass (2/2)
- Compiler suite: 265/266 (only pre-existing let_patterns X002)
- Any TML code using U128/I128 arithmetic is now correct
