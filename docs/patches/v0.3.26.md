# v0.3.26 — SIMD List Iteration

**Date:** 2026-04-15

## Summary

Pointer-stepping for-in loops over `List[T]` now bypass `next() -> Maybe[T]` entirely,
emitting the same phi-based pointer-stepping pattern as Rust's `slice::Iter`. This
eliminates the `Maybe` discriminant branch that blocked LLVM's LoopVectorizer.

## Changes

### Performance

- **`for x in list` pointer-stepping codegen** — `gen_for_pointer_stepping` in `loop.cpp`
  detects `ListIter`-based for-in loops and emits direct `phi ptr / icmp eq / load / gep`
  instead of calling `next() -> Maybe[T]` per iteration.
  - With checked arithmetic (`+`): **4.4B ops/s** (from 2.6B, 1.7× improvement)
  - With `wrapping_add`: **53.5B ops/s** (20.6× improvement, 3× faster than Rust)
  - LLVM LoopVectorizer produces `<2 x i64>` SIMD loads when loop body is branch-free

- **Remove personality from MIR functions** — MIR codegen no longer emits
  `personality ptr @__CxxFrameHandler3` on every function. Since MIR uses `call`
  (not `invoke`), personality was unnecessary and prevented LLVM `nounwind` inference.

### Codegen

- New `gen_for_pointer_stepping` method in AST codegen (`loop.cpp`) with:
  - Preheader: extracts `ptr`, `end`, `stride` from `ListIter` struct fields
  - Header: `phi ptr` with preheader/latch predecessors, `icmp eq ptr %ptr, %end`
  - Body: `load T, ptr %ptr, align 8` (direct element access, no Maybe)
  - Latch: `gep inbounds i8, ptr %ptr, i64 %stride` + `br` with `!llvm.loop` vectorize metadata

- Fixed stale loop metadata member names in `generate_support.cpp` — `loop_metadata_`
  and `loop_metadata_counter_` were referencing non-existent members on `LLVMIRGen`.
  Added proper declarations via `.inc` file and new `loop_metadata_nodes_` /
  `loop_metadata_node_counter_` members.

### Tests

- New regression test: `compiler/tests/compiler/iter/forin_list_pointer_stepping.test.tml`
  - Sum correctness (multiple elements)
  - Empty list (zero iterations)
  - Single element
  - Large list (1000 elements)
  - `break` inside for-in
  - `continue` inside for-in

## Remaining Vectorization Blocker

Checked arithmetic (`@llvm.sadd.with.overflow`) creates a branch in the loop body that
prevents SIMD vectorization for normal `+` operations. Using `wrapping_add` or
`unchecked_add` produces branch-free loops that LLVM vectorizes to `<2 x i64>`.
This is tracked separately from the pointer-stepping optimization.
