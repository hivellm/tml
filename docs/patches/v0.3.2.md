# v0.3.2 — Codegen Bug Fixes + Runtime Stability + `tml cv` In-Process

**Date**: 2026-04-12

## Highlights

- **K001 codegen fixes**: 3 AST codegen bugs fixed — enum discriminant type registration,
  non-generic type alias resolution, and boolean i64→i1 coercion
- **Runtime crash fix**: `InferCtx.next_var_id` replaced with `var_counter: List[I64]` to
  share the counter across value-copied instances; fixes STACK_BUFFER_OVERRUN in unify tests
- **`tml cv` in-process**: replaced `_popen("tml.exe check ...")` subprocess with an
  inline lexer→parser→type-checker call — fixes 0/91 false failures on Windows
- **27/28 compiler-tml tests pass** (was 20/27 before this release)

## Fixed

### Codegen (AST Path)

- **K001 enum discriminant**: enums were not registered in `struct_fields_` so
  `cast.cpp` could not find field-0 type when truncating i64→i32 in enum init.
  Fixed at 3 sites: `emit_enum_def()` (×2 in `enum.cpp`) and `llvm_types.cpp`.
- **Type alias resolution**: non-generic type aliases (e.g. `ValueId = I64`) were
  not resolved before IR emission — now looked up in the alias map in `llvm_types.cpp`.
- **Boolean coercion**: logical `and`/`or` operands now coerce i64→i1 before
  `llvm::IRBuilder::CreateAnd/Or` in `binary_ops.cpp`.

### Runtime (compiler-tml)

- **`InferCtx` shared counter**: `next_var_id: I64` was a scalar field — each copy
  of `InferCtx` (value type) had its own counter. Both callee increments were lost on
  return, so `fresh_var()` always returned `TypeVar(0)` in the caller. Fixed by
  changing to `var_counter: List[I64]` (one-element list); `List` holds a single
  `handle: *Unit` pointer, so all copies share the same heap-allocated element.
- **`unify_resolved` Primitive mismatch**: the Primitive→Primitive arm returned
  `false` on kind mismatch without pushing a `TypeError`. Downstream `assert(has_errors(ctx))`
  then failed with a noreturn assert handler, corrupting RBP to 0xAB (Windows debug heap fill)
  and causing ACCESS_VIOLATION at 0x8. Fixed by adding `ctx.errors.push(...)` before returning.

### `tml cv` Coverage Command

- **In-process type-check**: `type_check_file()` previously spawned `_popen("tml.exe check ...")`
  which launched `tml.exe` as a Windows cmd.exe subprocess. The compiler DLLs are not in
  the Windows system PATH (only in the Git Bash PATH), so all 91 files failed with exit
  code 2 (DLL not found). Replaced with a direct inline lexer→parser→type-checker call
  inside the same process. `preload_all_meta_caches()` is now called once before the batch.
  Result: **84/91 sources pass** (7 pre-existing type-check failures unrelated to K001).
