# TML v0.3.4 — 2026-04-14

## Fixed

### K001: bool/i32 mismatch in `icmp eq`/`ne` comparison emission (AST codegen)

**Root cause**: In `binary_ops.cpp`, when one operand of a `==` or `!=` comparison had
type `i1` (bool) and the other had a wider integer type (e.g. `i32`), the codegen emitted
`icmp eq i1 %wider_val, 1` — using the narrower `i1` instruction type for a register that
was actually `i32`. LLVM's IR verifier rejected this as an invalid instruction.

**Trigger**: The `Just(expr == 1)` pattern, where `expr` has type `I32` and the literal
`1` was typed as `i1` due to enum constructor context setting `expected_literal_type_`.
`is_bool` became `true` (because right operand was `i1`), setting `int_type = "i1"`, but
the left operand (`result: I32`) was loaded as `i32`, causing a type mismatch.

**Fix**: In `BinaryOp::Eq` and `BinaryOp::Ne` in `compiler/src/codegen/llvm/expr/binary_ops.cpp`,
when `int_type == "i1"` and one operand is a wider integer type, insert a `zext i1 %v to <T>`
instruction to widen the `i1` operand to the wider type before the `icmp`. This preserves
exact equality semantics (`zext i1 1 to i32 = 1`).

**Confirmed fix**: `std::json::Json::as_bool` and `std::json::Json::is_bool` now emit correct
`icmp eq i32` IR. `benchmarks/profile_tml/json_bench.tml --stage=parser:cpp` compiles and
runs successfully (exit 0).

**No regressions**: core 50/50, std 10/10, compiler 224/224.
