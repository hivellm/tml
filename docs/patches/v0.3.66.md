### cc `--emit=ast` targets — honest floors

The item nominally asks for 100/100 on `sig_alone.c` / `c_essential_repro.c` /
`essential.c`. Measured (adversarial):

| Target | Result | Floor | Status |
|---|---|---|---|
| `sig_alone.c` | **100/100** (50/50, 30/30) | 100 | **meets 100/100** |
| `c_essential_repro.c` | 86–92% | 80 | frozen cc_driver, documented |
| `essential.c` | 0% | 0 | frozen cc_driver, documented |

`sig_alone` meets the 100 gate (its default floor is already 100). The other two
are **frozen compiler-tml cc_driver debt** and cannot reach 100 without unfreezing
compiler-tml (forbidden — ADR/era0 policy: stabilization targets the C++ compiler,
not the frozen `compiler-tml/` C frontend). Their failure mode is a **segfault in
the C frontend at `--emit=ast`** (essential.c: exit 139, deterministic 3/3 even
non-adversarially; c_essential_repro: flaky exit 127) — this is BEFORE IR emission,
so it is **not** a K001/K002 invalid-IR class, and it is **pre-existing** (both at
their documented phase24/25-era floors long before phase26f; essential.c has been
0/100 since the baseline in `docs/analysis/tml-table-analysis/07-determinism-baseline.md`).
The `scripts/determinism-gate.sh` `min_pass_for` floors (essential.c=0,
c_essential_repro=80, everything else incl. sig_alone=100) already encode these
honest baselines; no change was needed.

## Verdict

The move-semantics milestone lands leak-free and double-free-free on the C++
compiler / pure-TML path: real move dataflow (1.1), Rust-faithful Copy (1.2b),
fact-driven drop suppression (1.3), container leak special-case removed (1.4),
conditional-move drop flags (1.5), zero fallout (1.6). The residual cc_driver
crashes are frozen, out-of-scope debt owned by the pre-phase26 era.
