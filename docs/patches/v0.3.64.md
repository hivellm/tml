# v0.3.64 — Conditional-move drop-flag elaboration (phase26f 1.5)

**Date:** 2026-07-16
**Phase:** phase26f (Move-Semantics Activation Milestone) — item 1.5
**ADR:** ADR-009 (B1-on-AST) · rulebook decision #12

## Summary

Both the syntactic `consumed_vars_` set (phase26f 1.3) and the monotonic
`moved_out` fact are **branch-insensitive**: a binding moved on only ONE path of
an `if`/`when`/`loop` was suppressed *unconditionally*, so the path where the move
did NOT happen **leaked** the still-live value. This release adds Rust-style
maybe-init + runtime **drop flags**: a binding moved on some paths but not all is
marked `conditionally_moved` by the borrow checker and its scope-exit drop is
guarded by a runtime `i1` flag instead of being statically suppressed.

Proof (join-debug, `TML_DROP_FACTS_DEBUG=1`), a conditional move
`if cond { let b = a }`:

```
[DROP-JOIN] var=a moved_out=1 cond_moved=1 consumed=0 ... DISAGREE-payoff
```

Before: `a` statically suppressed on both paths → leak when `cond` is false.
After: `a`'s drop is `if (flag) { drop }`, and the flag is cleared only on the
path that actually moved it.

## Checker — merge-point capture (approach 1)

The `if`/`when`/`loop` merges previously operated only on `InitState`
(`is_initialized`); `OwnershipState::Moved` is set by `move_value` and is
otherwise **monotonic** — never reset at branch boundaries, so the "mixed" state
was invisible. This release adds a parallel ownership snapshot:

- `BorrowEnv::save_ownership_state()` / `restore_ownership_state()` — snapshot and
  restore the per-place `state` enum (`checker_env.cpp`).
- `BorrowEnv::merge_ownership_branches(pre, branches)` — for each place moved
  within the construct: moved in ALL branches → static `Moved` (unchanged); moved
  in SOME → `Moved` **and** `conditionally_moved = true`. Places moved in no
  branch are restored to `pre`.
- Wired into `check_if` (both arms; the implicit not-taken `else` = `pre`),
  `check_when` (per-arm), `check_loop` and `check_for` (body vs zero-iteration
  `pre`) in `checker_expr.cpp`.

Crucially the **monotonic `moved_out` verdict is unchanged for every case** —
`Moved` is still set whenever a place is moved on any path — so the phase26f 1.3
static-suppression path (and its canaries) is byte-for-byte preserved. The only
addition is the `conditionally_moved` bit, exported on `PlaceOwnershipFact`.

## Codegen — runtime drop flags (AST path)

`LLVMIRGen` (`drop.cpp`, `llvm_ir_gen_stmt_let.cpp`, `expr/binary.cpp`):

- `register_for_drop`: when the ownership fact reports `conditionally_moved`,
  allocate an `i1` flag at the declaration (`alloca i1` + `store i1 true`), record
  it on the `DropInfo` and in `drop_flag_by_name_`.
- `note_move_for_flag(var)`: `store i1 false` at each **runtime move site** — the
  ~30 `mark_var_consumed` sites (function/enum/struct-init args, return, `x = y`,
  `when` bindings, `destroy`) plus the `let b = a` let-init ident move. Emitted in
  the move's own basic block so the flag tracks the path actually taken.
- `note_reinit_for_flag(var)`: `store i1 true` on reassignment (`x = new_value`) —
  re-arms the flag so a fresh value assigned after a conditional move is still
  dropped.
- `emit_scope_drops` / `emit_all_drops`: a flagged binding is dropped via
  `emit_conditional_drop` — `%f = load i1; br i1 %f, drop, cont` — never
  statically suppressed (`drop_suppressed_by_move` returns false for it).

Flags are emitted **only** for conditionally-moved bindings; unconditional moves
and never-moved bindings stay on the zero-cost static path (Rust-faithful).

## Canaries (adversarial corpus, all 15/15)

- `condmove_branch_probe` — move in a false `if` branch → the live handle must
  still be dropped (leak direction).
- `condmove_loop_probe` — move guarded inside a loop body (never runs) → leak
  direction.
- `condmove_when_probe` — move in one `when` arm, the other arm taken → leak
  direction.
- `condmove_taken_probe` — the move IS taken → the binding must NOT be dropped
  again (double-free direction, poison+quarantine).

Verified additionally out-of-band: partial move `let leaf = base.field` in a
false branch (no leak) and reassignment-after-taken-move re-arming the flag
(`w2` dropped exactly once).

## Known limitations (deferred, not regressions)

- **Partial (projection) conditional moves** are not flag-guarded — the checker's
  `conditionally_moved` is whole-place (mirrors the `moved_projections` deferral
  from phase26b Step 4). The tested partial-move-in-branch case is sound today
  because the field move is not force-suppressed; a projection-level flag is
  future work.
- **Drop-on-reassign for handle structs** (`var a = X; a = Y` not dropping the old
  `X`) is a **pre-existing** gap (reproduced with no conditional move / no flag),
  orthogonal to this release.
