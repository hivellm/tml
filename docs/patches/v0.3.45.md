# v0.3.45 — Structural `Heap[T]` → `Shared[T]` migration in C-frontend type system (phase24g)

**Released**: 2026-05-02
**Branch**: feat/self-hosting-compiler
**Task**: `.rulebook/tasks/phase24g_heap-rc-or-borrow-language-fix/`

## Summary

Replaces the unique-owning `Heap[T]` pointer in the C-frontend type system
with the existing refcount-shared `Shared[T]` pointer (defined at
`lib/core/src/alloc/shared.tml`). This is the structural fix for the
Heap-borrow-drop bug class that phase24c, 24d, 24e, and 24f had patched
piecemeal with `into_raw`/`from_raw` workarounds. With `Shared[T]`,
aliasing `HashMap.get` / `List.get` results is safe by construction —
each `.duplicate()` is a refcount-increment, not a pointer copy that
later double-frees on drop.

## Bug class eliminated

`HashMap[K, Heap[T]].get(k)` returns `Heap[T]` BY VALUE whose internal
`ptr` field aliases the bucket's allocation. When the local handle drops
at end-of-scope, `Heap`'s `Drop` impl calls `mem_free(ptr)`, freeing the
bucket's allocation. The next `HashMap.get(k)` returns a `Heap` whose
`ptr` is dangling — `t.get()` then dereferences freed memory.

This pattern appeared throughout `compiler-tml/src/cc/`:

- `base_to_ctype` Typedef / StructRef / UnionRef / EnumRef arms (phase24c, 24d)
- `apply_declarator` Func arm constructing nested CFuncType (phase24e)
- `declarator_name_heap` recursing through `Heap[CDeclarator]` (phase24f)
- `cp_parse_for_stmt` capturing first CDecl from for-init (uncommitted patch in phase24f)

Each was patched with `into_raw()` to neutralize the local's drop, plus
deep-clone via a hand-rolled `impl Duplicate for CType`. Cumulative
result: ~80 lines of brittle workaround code, plus `declarator_name_value_leak`
that walked CDeclarator while leaking every Heap layer.

## Structural fix

`Shared[T]` is reference-counted: `.duplicate()` increments the count,
`Drop` decrements; the allocation is freed only when the count reaches
zero. Aliasing safe by construction — no leak hacks, no `into_raw`.

## Workarounds removed

- `into_raw()` + `Heap::from_raw()` chains in `base_to_ctype` Typedef /
  StructRef / UnionRef / EnumRef arms — replaced with one-liner
  `env.X.get(tag).duplicate()`.
- Deep-clone path in `impl Duplicate for CType` — now each arm just
  calls `.duplicate()` on the `Shared` payload (refcount-inc, O(1)).
- `declarator_name_value_leak` helper (24 lines + 17 lines of
  per-variant `into_raw()` chains in `declarator_name_heap`) —
  collapsed to `return declarator_name(d.get())`.
- For-init `into_raw + from_raw` patch (commit `6c48664a`) — replaced
  with `let first: Shared[CDecl] = dp.decls.get(0).duplicate()`.

Net code reduction: ~80 lines of workaround code removed.

## Migration notes for future C-frontend work

- When adding a new field to `CType`, prefer `Shared[CType]` over
  `Heap[CType]` if the field is read-back through a HashMap or List slot.
- `Shared[T]` does not provide `into_raw()` or `is_unique()`-based
  ownership transfer in the same way `Heap[T]` does; if you genuinely
  need unique ownership semantics with no aliasing, keep `Heap[T]` (e.g.
  `Heap[CExpr]` inside `CExpr::Binary` — the AST is a tree, no
  aliasing).
- Cross-list copies of `Shared[T]` values must call `.duplicate()` to
  refcount-inc — see `cp_parse_translation_unit` for the canonical
  pattern: `unit.decls.push(pd.decls.get(i).duplicate())`.
