# v0.3.79 — Shared-stdlib fast-path ENABLED: zero-body bootstrap + reference-driven emission (phase43a Option B, F-006)

**Date:** 2026-07-18

## Summary

The shared-stdlib fast-path — disabled since its inception behind four recorded
blockers — is now **implemented, fixed, and enabled** (with an amortization
heuristic). The architecture is "Option B": the bootstrap emits **zero function
bodies**, capturing only the semantic index plus the two pending-body maps;
each worker restores them and the already-wired reference-driven emission
(`emit_referenced_library_definitions`) generates exactly the bodies that
worker references — the same set the normal path emits.

**Gate: zero divergence, both modes.** Fast-path ON: core/hash 14/14, core/str
33/33, std/json 23/23, compiler/borrow 12/12, core/alloc 43/44 (documented
floating concurrency miss). Fast-path OFF (slow-path regression check for the
mangling change): all green.

Bootstrap cost: **~16 min (eager, failing) → ~34 s (zero-body, working)**.

## The architecture (Option B)

- The bootstrap runs with a new option `library_skip_user_code` which keeps
  lazy deferral ACTIVE (the old `library_ir_only` mode disabled it, eagerly
  compiling ~5000 never-exercised bodies — the source of the K001 treadmill,
  which is now eliminated **by construction**: a body nothing references is
  never compiled).
- `CodegenLibraryState` gains `pending_library_methods` / `pending_library_funcs`
  (AST pointer + module-context entries). Capture is hard-gated per entry on
  `GlobalASTCache::should_cache` — measured `skipped=0`, so every entry's AST
  is process-global and worker-safe.
- The eager flush loop in `generate_library_only_ir` (dead code that would have
  resurrected with `in_library_body_ == false` — the Str-temp use-after-free
  hazard) is skipped under the new mode. The reference-driven path sets
  `in_library_body_ = true` correctly, structurally eliminating that hazard.
- The stdlib `.obj` compile and its mtime cache-check are DELETED — the object
  was written to disk and linked by nothing (`g_stdlib_obj_path` had no reader).
- Amortization heuristic: the bootstrap costs ~30 s per process and its state
  cannot be persisted (AST pointers), so it only runs when the test run has
  ≥ 32 files. `TML_STDLIB_FASTPATH=1|0` forces it on/off (the gate runs forced).

## Root-cause fixes required to reach green (each found by reproduction)

1. **Conditional runtime types mirror** (`runtime.cpp`): the bootstrap emits
   `RawThread`/`RawPtr`/`HashMapIter` defs into its own headers and registers
   them in `struct_types_` (captured) — `gen_struct_decl` then early-returns
   forever, so the textual def exists nowhere a worker can see. A worker whose
   own import scan didn't need the category pasted library code referencing
   `%struct.RawThread` with the type undefined. Workers now emit the
   conditional types whenever cached state is present.

2. **Emission-ledger truth filter** (`generate_support.cpp`): the bootstrap's
   `generated_functions_` claimed **1836** bodies of which only **4** had
   captured text (emission phases outside the two capture snapshots). Captured
   ledgers are now filtered against the captured text — an entry may only claim
   a symbol whose `define` is actually present. Without this, every downstream
   dedup guard trusted a lie and skipped generation of bodies that existed
   nowhere.

3. **Vtable body-availability check** (`dyn.cpp`): `emit_vtables` trusted the
   restored `functions_` index as proof a method body "was compiled in this
   unit". Entries whose body is neither defined in the IR text nor pending
   emission now fall through to the existing imported-module-skip /
   default-method logic.

4. **Symbol-divergence alias bridge** (`runtime_modules_library.cpp`): when the
   pending-map key and the regenerated symbol disagree (module-identity drift),
   the referenced name is bridged with an `internal alias` to the produced body.

5. **Demangling recovery** (`runtime_modules_library.cpp`): unresolved
   `@tml_N…E` refs are demangled into (module…, Type, method) segments; a
   matching pending entry is generated + aliased, or a registered impl is
   queued as a `PendingImplMethod` — catching methods whose call-site dispatch
   skipped queueing because the restored `functions_` index satisfied an
   earlier branch (primitive impl methods, `method_impl.cpp:1249+`).

6. **JSON runtime declare dedup** (`derive/deserialize.cpp`): the derive block
   emitted `declare i64 @tml_json_parse(ptr)` while the pasted bootstrap text
   declares the same symbol as `dso_local` — an "invalid redefinition". The
   derive block now emits `dso_local` and respects/registers
   `declared_externals_`.

7. **THE ROOT OF THE DIVERGENCE CLASS — deterministic
   `find_module_for_type`** (`llvm_utils.cpp`): when a type is registered in
   more than one module (re-exported submodule: `Json` in `std::json` AND
   `std::json::types`; `FormatSpec` in `core::fmt` and `core::fmt::rt`), the
   module chosen becomes part of the mangled symbol — and the choice was
   "first hit in an unordered_map", i.e. **non-deterministic across LLVMIRGen
   instances**. The bootstrap deferred a body under one identity while the
   worker's call site mangled the other. The slow path only escaped because
   caller and generator share one instance. Now all matches are collected and
   the lexicographically smallest module wins — arbitrary but stable
   everywhere. Fixes 1–6 remain as defense-in-depth; this removes the cause.

8. **Supplemental module scan** (`generate.cpp`): implements the safety net
   `processed_module_paths` was captured for but never had. Module loading is
   use-driven and `test_bootstrap.tml` uses nothing, so re-exported submodules
   (observed: `std::json::serialize`) can be absent from the captured state
   entirely. Workers now run the module scan restricted to modules NOT covered
   by the bootstrap (no-op when coverage is complete). The scan gained the
   `skip_modules` parameter this requires.

9. **Sub-fixes**: bootstrap phantom import paths + `send_once` visibility
   (landed earlier as `101fa288`); dead `[LAZY_LIB] UNRESOLVED` warning made
   live (it was gated on a round the loop never reached — silent unresolved
   refs were this session's most expensive failure mode); `[FORCE-TRACE]`
   debug prints removed; `TML_DUMP_FAILING_IR=<path>` added as a permanent
   env-gated facility to dump IR that fails LLVM parsing (the in-process
   backend otherwise never touches disk, making K001 line/column references
   undiagnosable).

## Verification

- Fast-path ON (forced): 5/5 acceptance suites at baseline, `--no-cache`.
- Fast-path OFF: 4/4 re-checked green (the `find_module_for_type` change
  affects slow-path mangling too).
- Determinism: `determinism-gate.sh 10` (result recorded in tasks.md).
- `[LIB_STATE]` capture telemetry: 3264 methods + 1832 funcs deferred,
  0 skipped (AST-cache gate is a no-op guarantee, not a live risk).

## Notes

- Per-file emitted IR dropped from ~22.5k lines to ~3-8k (referenced set only).
- The bootstrap state is process-local; single-suite runs below the 32-file
  threshold use the normal path (a small targeted run would pay ~30 s to save
  less). MCP/dev-loop UX is unchanged; full runs amortize once.
- F-007 (decls-only workers + shared object with external linkage) remains
  future work; its economics changed — test objects now embed only referenced
  bodies, not the full ~5000.
