# v0.3.18 — Remove Embedded LLD, Use Native OS Linker

**Date:** 2026-04-15
**Branch:** feat/self-hosting-compiler

## Summary

Removes statically-linked LLD libraries (lldCOFF, lldELF, lldMachO,
lldMinGW, lldWasm + 7 transitive LLVM dependencies) from
`tml_codegen_x86.dll`. Linking now always uses the native OS linker as
a subprocess, reducing the codegen DLL from 78 MB to 58 MB (−26%).

## Changes

### `compiler/src/backend/lld_linker.cpp`

- Removed all in-process LLD code: the global mutex, poison state tracking,
  and 15-second timeout watchdog thread.
- Linking now always goes through the subprocess path:
  - **Windows**: `link.exe` (MSVC) primary, `lld-link.exe` fallback
  - **Linux/macOS**: `ld` primary, `ld.lld` fallback
- Removed `force_subprocess_lld` flag — subprocess is now the only mode.

### `compiler/CMakeLists.txt`

- Removed LLD static library dependencies from `tml_codegen_x86` target:
  `lldCOFF`, `lldELF`, `lldMachO`, `lldMinGW`, `lldWasm`, and their
  transitive LLVM dependencies (`LLVMOption`, `LLVMBinaryFormat`, etc.).

## Results

| Metric | Before | After |
|--------|--------|-------|
| `tml_codegen_x86.dll` size | 78 MB | 58 MB (−26%) |
| Compiler tests | 189/189 | 189/189 (zero regressions) |
| Link mechanism | In-process LLD (flaky, global mutex) | Subprocess (robust) |
