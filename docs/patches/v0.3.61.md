# v0.3.61 — Rust-faithful Copy classification, blast radius 53 → 0 (phase26f 1.2b)

**Date:** 2026-07-16
**Phase:** phase26f (Move-Semantics Activation Milestone) — item 1.2b
**ADR:** ADR-009 (B1-on-AST) · rulebook decision #12

## Summary

v0.3.60 activated the move dataflow and measured a 53-error / 7-file blast
radius under `TML_STRICT_MOVES=1`, of which ~96% were idiomatic implicit-copy
sites the classifier should never have called moves. This release closes the
three classifier gaps recorded in `specs/blast-radius/spec.md`, making the Copy
classification Rust-faithful and — critically — making the exported `moved_out`
facts **reliable** (no false moves), the prerequisite for item 1.3's
drop-suppression swap.

**Re-measuring the identical 176-file corpus: 0 move-errors / 0 files
(was 53 / 7).** Default behaviour is unchanged — the flag is still OFF by
default; this only changes what the flag *would* flag.

## `is_copy_type` (borrow/checker_core.cpp)

1. **Raw pointers are Copy.** `*T` / `*mut T` (`PtrType`) now classify as Copy,
   exactly as Rust treats `*const T` / `*mut T`. Copying a raw pointer
   duplicates the address only.
2. **Transparent type aliases are resolved.** A named type that is a type alias
   (e.g. `Ptr = *Unit`) is resolved to its underlying type — consulting the
   local alias table, the module registry, and finally the **global library
   cache** (so `Ptr[U8]` reused across allocator calls is Copy even in a file
   that only imports `core::alloc`, never `core::ptr`). Resolution is memoised
   per name; the global-cache scan runs at most once per distinct alias name.
3. **Copy/Drop are mutually exclusive.** A type with an `impl Drop` never
   classifies as Copy, even if a (malformed) `impl Copy` exists — the Rust rule,
   enforced defensively so a bit-copy can never duplicate a resource whose
   destructor would then run twice.
4. The pre-existing `type_implements(name, "Copy")` consult is now backed by
   actual stdlib derives (below).

## Stdlib Copy derives

`@auto(duplicate)` + `impl Copy for T {}` — the idiomatic pattern already used by
`Ipv4Addr`, `Duration`, etc. — added to the trivially-copyable value types the
blast radius identified (all all-primitive fields, no `Drop`):

- **`Layout`** (`lib/core/src/alloc/layout.tml`) — two `I64` fields; matches
  Rust's `core::alloc::Layout: Copy`. Dominated the radius (42/53 errors).
- **`Interval`** (`lib/std/src/collections/interval_tree.tml`) — two `I64`
  fields; passed by value to `overlaps`/`equals` and reused.
- **`Point`** (`compiler/tests/compiler/insertvalue_struct.test.tml`) — two
  `I64` fields; the test literally depends on "still valid after pass-by-value".

## Method-arg param-kind — SAFE-FALLBACK (under-move)

The borrow checker has no method resolution, so it cannot distinguish a `ref T`
method parameter (a borrow) from a by-value one. Recording every bare-identifier
method arg as a move (the v0.3.60 behaviour) **over-counted** `moved_out` for
`ref` params — which, once item 1.3 drives drop suppression from `moved_out`,
would suppress a needed drop = **leak**. Fixed by **not** setting `moved_out`
for method args: param-kind is treated as UNKNOWN, and under-move is the safe
direction (the syntactic `consumed_vars_` set still drives drop suppression
until 1.3 swaps it — today's status quo). A full fix (thread each resolved
method signature from the type checker into a `MethodCallExpr` side table,
mirroring the v0.3.60 `IdentPattern` type recording) is deferred: the type
checker's `check_method_call` has many resolution branches
(named/generic/builtin/module-cache) and a partial recording would silently
leave the unrecorded ones over-counting.

## Note on the double-free probe

`scripts/fixtures/double_free_probe.tml` (the only Category A "genuine bug
caught" at v0.3.60) is **no longer** a strict-moves error, because its `p` is a
raw pointer and raw pointers are now Copy. This is Rust-faithful — Rust does not
track raw-pointer double-free as use-after-move either. The double-free is still
a real defect; catching it belongs to a leak/UAF checker, not the move checker.

## Verification

- **Blast radius (flag ON, same 176 files): 0 errors / 0 files** (was 53 / 7).
  Per-corpus: determinism 2→0, core/alloc 42→0, collections 3→0,
  compiler-first-25 4→0.
- **Flag OFF regression:** determinism gate **22/22** (adversarial ON);
  core/alloc **44/44**, core/str **32/32**, std/json **23/23**; `interval_tree`
  passes. The 4 collections failures (`arraylist`, `class_coverage`,
  `collections_advanced`, `stack`) are the **pre-existing phase27a K001 family**
  (`'%tN' … '{ i64, i64 }' but expected 'i32'`), none referencing the modified
  types; proven independent by neutralising the stdlib derives and reproducing
  the identical K001 with `--no_cache`.
- **Join-proof (`TML_DROP_FACTS_DEBUG=1`):** `let y = x` (owning) →
  `moved_out=1`; `Layout` passed by value twice → no `moved_out` (Copy);
  `refcount_bleed_probe` all `moved_out=0`, `tml run` exit 0.
