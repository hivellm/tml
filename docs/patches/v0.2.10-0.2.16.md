## v0.2.10 — 2026-04-03

## Summary

Codegen architecture overhaul + NestJS-style HTTP decorators. 7 codegen tasks completed (121 items), bringing TML's MIR codegen closer to Rust's quality. Plus @Controller on types, @Param/@Query/@Body/@Headers on function parameters, and DI documentation.

---

## Highlights

- **MIR validation pass** — null types now abort compilation (Rust ICE behavior), not silently fall back to i32
- **Centralized ABI module** — `PassMode`, `FnABI`, `compute_fn_abi()` replace scattered `starts_with("%struct.")` checks
- **pub use re-exports** — codegen now follows re-exports through module registry
- **CGValue typed wrapper** — foundation for replacing loose `(reg, type)` pairs with typed values
- **Response builder restored** — proper middleware imports (cors, security, etag, cache_control)
- **@Controller on types** — `@Controller("/prefix")` prepends to `@Get`/`@Post` method paths
- **@Param/@Query/@Body/@Headers** — decorator support on function parameters (AST → MIR pipeline)

---

## Fixed (Codegen — Compiler)

### pub use re-exports invisible to codegen
- `module.cpp`: `lookup_function`/`lookup_behavior` now follow `pub use` re-exports recursively with visited set to prevent cycles
- `runtime_modules_tml.cpp`: transitive import expansion follows re-export source modules, ensuring their functions get `declare`/`define` in IR
- `env_module_load.cpp`: file-loading path now processes `private_imports` (parity with GlobalModuleCache and binary meta paths)

### MIR null type → ICE (was: silent i32 fallback)
- New `mir_validate.cpp` pass runs after MIR building, before codegen
- Checks every instruction for null type, every block for terminator, every function for entry block
- On failure: logs all issues → `[ICE] MIR validation failed` → aborts compilation
- 23 `[CG-I32]` warning annotations added as defense-in-depth (zero fire across full 1659-test suite)

### Centralized ABI module
- New `abi.hpp`/`abi.cpp`: `PassMode` (Direct, Indirect, Ignore, Pair), `ArgABI`, `FnABI`
- `classify_type()` dispatches on MIR type variant (not string prefix matching)
- `compute_fn_abi()` computes full function ABI from `mir::Function`
- `is_aggregate_llvm_type()` replaces 6 scattered `starts_with("%struct.")` checks — now consistently covers `%struct.`, `%enum.`, `%class.`, `%union.`, `%tuple.`
- `fn_abi_cache_` replaces `func_param_types_` map in MirCodegen
- `ArgABI.mir_type` stores original MIR type for call-site coercion checks

### CGValue typed wrapper (Phase 1)
- New `cg_value.hpp`/`cg_value.cpp`: `CGValueKind` (Immediate, Address, FatPointer, ZeroSized)
- `CGValue` struct with `is_aggregate()`, `is_pointer()`, `is_zero_sized()` queries
- `cg_to_address()`/`cg_to_immediate()` conversion helpers
- Foundation for Phase 2-4 integration (replacing `value_types_` map)

## Fixed (Library)

### ETag FNV-1a integer overflow
- `etag.tml`: changed hash variables to `U64`, multiplication to `wrapping_mul()`, division to bitshift
- FNV-1a intentionally wraps — TML's checked `*` operator was panicking

### Response builder middleware imports
- `response_builder.tml`: restored imports from `std::http::middleware::{cors, security, etag, cache_control}`
- `build_http_response()` now calls proper middleware functions instead of inlining header strings

## Language Features

### Optional chaining (`?.`)
```tml
let name = parse(json_str)?.get_string("name")  // Maybe[Str]
let city = user?.address?.city                    // field chaining
```
- Lexer: `?.` tokenized as `QuestionDot`
- Parser: creates `MethodCallExpr`/`FieldExpr` with `optional_chain=true`
- Type checker: unwraps `Maybe[T]`, resolves on `T`, returns `Maybe[U]`
- Codegen: branches Just/Nothing, auto-flattens `Maybe[Maybe[T]]` → `Maybe[T]`

### let-else guard clause
```tml
let Just(name) = parse("hello") else { return }
println(name)  // flat, no nesting
```
- Fixed nullable Maybe GEP codegen bug
- Removed mandatory type annotation — infers from expression
- Works with `continue`, `return`, `break`

## Compiler

### TML Self-Hosting Frontend (phase13d)

The TML self-hosting lexer+parser (`main_frontend.exe`) is now the default compilation frontend:

- **`tml build <file.tml>`** → uses TML lexer/parser (was C++ by default)
- **`tml run <file.tml>`** → uses TML lexer/parser (was C++ by default)
- **`tml test`** → test compilation uses TML parser (was C++ by default)
- **Fallback**: `--stage=parser:cpp` forces C++ lexer/parser on all three commands

The hybrid pipeline (`--stage=<name>:<impl>`) now accepts both `"tml"` and `"cpp"` as valid `<impl>` values:

```bash
tml build myfile.tml                    # TML frontend (default since v0.2.15)
tml build myfile.tml --stage=parser:cpp # Force C++ frontend
tml test lib/core/tests --stage=parser:cpp  # Test with C++ parser fallback
```

### Phase 13 Self-Hosting Timeline

### Implementation Details

The TML frontend operates as a subprocess: `main_frontend.exe <source.tml>` writes a binary-serialized `Module` AST to stdout. The C++ host reads and deserializes it via `serial::read_ast()` in `query_core.cpp`. The `--stage=parser:tml` → `--stage=parser:cpp` fallback uses the existing `stage_overrides` map in `QueryOptions`.
