# v0.3.69 — Suite-mode test aggregation by default (phase41a, F-005)

**Date:** 2026-07-17 · **Branch:** `fix/era0-stabilization`

## Summary

`tml test` now aggregates multiple test files into one native EXE by default for
non-coverage runs (**25 files/EXE**), replacing the one-EXE-per-file model that
made a full run do ~2066 separate LLVM-codegen + LLD-link + process-spawn cycles.

- **Link/codegen cycles per full run: 2066 → 176 suites = 11.7×** reduction
  (measured 14× on `lib/core/tests/hash`: 14 exes → 1).
- `--coverage` still forces per-file grouping (coverage requires it); the new
  `--no-suite` flag forces per-file on demand.
- `--unified` (single mega-binary) was evaluated and **disqualified as the
  default**: it has no result cache and a link failure exits 0 with zero tests
  (silent loss). Suite-mode keeps the ADR-004 result cache and per-test reporting.

## Correctness (no silent result loss under aggregation)

- **Compile-failure isolation:** a test file that fails to compile is reported as
  a failed test + compile error (COMPILE SKIP) while its sibling files still
  compile into the aggregated EXE and run.
- **Crash/timeout isolation:** a test that kills the aggregated subprocess
  (per-test in-EXE watchdog, exit 99) is attributed as the offender, and the
  never-started sibling files are re-run individually — no "NOT RUN" silent loss.
- **NDJSON per-test attribution fix:** `test_pass`/`test_fail` events now carry
  the original test index (previously emitted a sequential position, which
  misattributed results when compile-failed files left gaps in a suite).

## Codegen linkage fix (blocker for any multi-file link)

`__tml_register_routes` (HTTP route registration) and `__tml_route_thunk_N` were
emitted with **external** linkage in every test object even though all references
are module-local — so any aggregated (multi-file) link failed with
`lld-link: duplicate symbol: __tml_register_routes`. They now get **internal**
linkage under `force_internal_linkage` (`generate_entry.cpp`, `mir_codegen.cpp`).

## Determinism gate

`scripts/determinism-gate.sh` now refreshes the corpus with `--no-suite` (the
determinism corpus contract runs one exe per repro file; aggregation would
otherwise run stale per-file exes). Floors unchanged. Gate green at 28/28; the
transient 27/28 seen during development was the documented-flaky legacy
`c_essential_repro` (floor 80, exit-127 aliasing crash, phase24/phase27c family)
hitting an unlucky 10-run sample — 47/50 = 94% on re-measure, independent of this
change (all pure-TML codegen sentinels remained 100/100).

## Tests

`compiler/tests/cli/test_aggregation.sh` — 16 checks: default aggregation,
`--no-suite`/`--coverage` per-file, compile-failure isolation, crash/timeout
offender attribution + sibling re-run, aggregated-vs-per-file count parity.
Result: 16/16 pass; `core/hash` 14/14 identical in both modes.

## Verification note

The full-run rigorous before/after wall-clock A/B was blocked because a full run
on the pre-flip binary crashed at ~1080/2066 (0xC0000409 — the pre-existing
phase27c flaky, not introduced here); parity is therefore established same-binary
(new default vs `--no-suite`) plus per representative suite. The ≥10× gate is met
on the link-cycle count (11.7× full-run, 14× core/hash) with zero result
divergence.
