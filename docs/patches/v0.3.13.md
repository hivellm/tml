## Summary

Named Return Value Optimization (NRVO) implemented in the MIR→LLVM codegen path.

When a `sret`-returning function calls another `sret`-returning function and
immediately returns that result, the intermediate alloca+load+store sequence
is eliminated by forwarding `%sret` directly to the callee's hidden sret slot.

**Before (3 instructions):**
```llvm
%sret.slot.0 = alloca %struct.Point, align 8
call void @make_point(ptr sret(%struct.Point) %sret.slot.0, i64 %x, i64 %y)
%v = load %struct.Point, ptr %sret.slot.0, align 8
store %struct.Point %v, ptr %sret, align 8
```

**After (1 instruction):**
```llvm
call void @make_point(ptr sret(%struct.Point) %sret, i64 %x, i64 %y)
```

---

## Implementation

### Pre-scan phase (`mir_codegen.cpp`)
At function entry, a pre-scan over all blocks identifies NRVO candidates:
- Find all `CallInst` results whose callee is in `sret_functions_`
- Check whether any `StoreInst` stores that result to the sret param
- Build `nrvo_call_results_` set (ValueIds eligible for NRVO)

### Emit phase (`instructions_call.cpp` — `emit_sret_call`)
Before allocating the intermediate sret slot, check NRVO eligibility:
- If `inst.result` is in `nrvo_call_results_`, pass `current_func_sret_param_` directly
- Map `cg_values_[result]` to an `Address` pointing at `%sret`
- Return early — no alloca, no load

### Store skip (`instructions.cpp` — `StoreInst` handler)
When an NRVO call result is stored to the sret param, skip the store:
- The write already happened during the call; the store would overwrite with itself
- Guarded by `nrvo_call_results_.count(i.value.id) > 0`

### New per-function state (`mir_codegen.hpp`)
```cpp
bool current_func_has_sret_;
std::string current_func_sret_param_;
mir::ValueId current_func_sret_param_id_;
std::unordered_set<mir::ValueId> nrvo_call_results_;
```
