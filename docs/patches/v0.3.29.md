# v0.3.29 — SSO for Text + String Interning

**Date:** 2026-04-16

## Performance

### Small String Optimization (SSO) for `Text`

The `Text` type now uses a 24-byte tagged-union struct with inline storage for
short strings (≤23 bytes), eliminating heap allocation entirely:

| String length | Before (ns/op) | After (ns/op) | Improvement |
|---------------|-----------------|----------------|-------------|
| 5 chars       | 48              | 0 (DCE'd)      | ∞           |
| 10 chars      | 47              | 0 (DCE'd)      | ∞           |
| 30 chars      | 46              | 26             | 44%         |

**Layout:**
- **Inline mode** (`_w2 < 0`): bytes 0-22 = string data, byte 23 = `0x80 | len`.
  Zero heap allocations.
- **Heap mode** (`_w2 ≥ 0`): `_w0` = data pointer, `_w1` = length, `_w2` = capacity.
  One heap allocation (data buffer only — no separate header).

Previously `Text` was `{ handle: *Unit }` (8 bytes) pointing to a 24-byte heap
header which pointed to a separate data buffer — two allocations per string.

### String Interning for Compiler Identifiers

New `compiler-tml/src/intern.tml` module provides `InternTable`:
- `intern(s: Str) -> I64`: deduplicate strings, return integer ID
- `lookup(id: I64) -> Str`: reverse lookup
- Wired into the TML lexer: all identifier tokens use interned strings

### Codegen: SSO-aware Text Printing

Updated `io.cpp` to handle the new SSO layout when printing `Text` values
via `println()`. Uses a branch: heap mode does `inttoptr`, inline mode
stores the struct to stack and null-terminates.

## Files Changed

- `lib/std/src/text.tml` — SSO tagged-union layout (complete rewrite)
- `compiler/src/codegen/llvm/builtins/io.cpp` — SSO-aware Text printing
- `compiler-tml/src/intern.tml` — new InternTable module
- `compiler-tml/src/lexer/lexer.tml` — identifier interning

## Breaking Changes

- `Text` struct changed from `{ handle: *Unit }` (8 bytes) to
  `{ _w0: I64, _w1: I64, _w2: I64 }` (24 bytes). Any code that directly
  accessed `Text.handle` via `lowlevel` must be updated.
- No public API changes — all `Text` methods retain the same signatures.
