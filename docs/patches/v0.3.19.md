# v0.3.19 — File::sync() and File::datasync()

**Date:** 2026-04-15
**Branch:** feat/self-hosting-compiler

## Summary

Adds `File::sync()` and `File::datasync()` methods to the standard library
file module. These guarantee that written data reaches permanent storage,
which is essential for database WAL (Write-Ahead Log) durability, config
file writes, and any safety-critical persistence.

Requested by the UzDB AI agent for their database WAL implementation.

## API

```tml
use std::file::file::File

var f: File = File::open_write("wal.log")
f.write_str("WAL entry 1\n")
f.sync()       // fsync — flush data + metadata to disk
f.datasync()   // fdatasync — flush data only (faster on Linux)
f.close()
```

## Changes

### `lib/std/runtime/file.c`

- `file_sync(TmlFile*)` — calls `fflush()` then:
  - Windows: `_commit(_fileno(handle))`
  - Unix: `fsync(fileno(handle))`
- `file_datasync(TmlFile*)` — calls `fflush()` then:
  - Linux: `fdatasync(fileno(handle))`
  - Windows/macOS: falls back to `fsync()`/`_commit()`

### `lib/std/src/file/file.tml`

- `File::sync() -> Bool` — FFI wrapper for `file_sync`
- `File::datasync() -> Bool` — FFI wrapper for `file_datasync`

## Platform Behavior

| Platform | `sync()` | `datasync()` |
|----------|----------|--------------|
| Windows  | `_commit(fd)` | `_commit(fd)` (no separate fdatasync) |
| Linux    | `fsync(fd)` | `fdatasync(fd)` |
| macOS    | `fsync(fd)` | `fsync(fd)` (no fdatasync on macOS) |
