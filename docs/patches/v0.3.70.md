## F-012 — LLVM backend re-initialized on every object compilation (RESOLVED)

- Before: `compile_ir_string_to_object` / `compile_ir_string_to_buffer`
  (`compiler/src/cli/builder/object_compiler.cpp`) constructed a fresh
  `backend::LLVMBackend` and called `initialize()` on **every** call — per test
  file and per dispatcher — creating and disposing an `LLVMContext` each time.
- After: both route through a new `get_thread_local_llvm_backend()` that constructs
  and `initialize()`s exactly one backend per worker thread and reuses it (and its
  `LLVMContext`) across every object compilation on that thread. LLVM target init
  was already process-global (`std::call_once` in `initialize()`); the eliminated
  cost is the per-object context lifecycle. Each call still parses its IR into a
  fresh module and disposes it after emitting — no module state leaks across reuse.
- Behaviour-transparent (identical object bytes). Parity on clean suites, zero
  divergence: `core/hash` 14/14, `compiler/borrow` 12/12, `core/str` = the same 5
  pre-existing K001 `mem::replace` failures (byte-identical), `core/alloc` 43/44
  (the one miss `shared_sync_edge` is a pre-existing flaky concurrency test that
  passes 1/1 in isolation).

## F-006 / F-007 — shared-stdlib fast-path (root-caused, deferred)

Reproduced (scratch re-enable of `build_stdlib_object`): with a minimal bootstrap
the fast path engages (state captured in 20 s, 1235 KB IR) but every test object
**and the shared stdlib object itself** fail with
`use of undefined value '@tml_N4core7runtime3mem7replaceE_R1T1T'` — the
un-monomorphized generic template symbol for `core::runtime::mem::replace[T]`
(defined at `lib/core/src/runtime/mem.tml:205`).

Root cause (traced): generic **module free-function** calls have no call-site
re-mangle+queue branch in `call_user.cpp` (generic **`Type::method`** calls do,
`call_user.cpp:595–632`); when `gen_call_generic_func` misses (its
`pending_generic_funcs_` lookup fails, e.g. when the callee's module isn't fully
registered under a partial/scoped bootstrap) the call falls to the declaration-name
fallback (`call_user.cpp:452`) and emits the template symbol with **no queued
definition**. This is the **same error** as the pre-existing 5× `core/str` K001
failures, i.e. a phase27a K001-family generic-substitution root — not a
fast-path-only bug.

Full enablement additionally requires: a **per-suite-scoped, complete** bootstrap
(the monolithic `test_bootstrap.tml` imports ~12 *phantom* `pub mod` modules
declared in `lib/core/src/mod.tml` with no source file, so its typecheck aborts;
an all-loadable-modules bootstrap **timed out >500 s** just building the shared
object); capturing `generated_impl_methods_output_`/`generated_impl_methods_` in
`CodegenLibraryState` (avoids the "I32::duplicate redefinition" local-vs-cached
collision); and the i64/i32 range-iterator width (phase27a K001 Class 2).

**Proposed minimal path:** (1) phase27a — add a generic free-function call-site
monomorphization branch in `call_user.cpp` mirroring the `Type::method` block +
resolve range/iterator width from the registered signature; (2) a per-suite-scoped
shared-object redesign of `build_stdlib_object` (build from the suite's transitive
imports, not all of lib/std); (3) capture the impl-method dedup sets. Left off by
default until (1) lands, since enabling regresses clean suites.
