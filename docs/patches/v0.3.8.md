# v0.3.8 — Boolean Short-Circuit Fix (phase0f)

**Date**: 2026-04-14  
**Branch**: feat/self-hosting-compiler

## Summary

`and` and `or` now correctly implement short-circuit evaluation. Previously, both operands were always evaluated eagerly because the operators fell through to `gen_binary_ops` which already had both SSA values computed. This release adds a 2-block phi layout that skips RHS evaluation when the LHS determines the result.

## Changes

### compiler/src/codegen/llvm/expr/binary.cpp

Added short-circuit block layout before delegating to `gen_binary_ops`:

- **`a and b`**: if `a` is false, branch directly to merge block; `b` is never evaluated.
- **`a or b`**: if `a` is true, branch directly to merge block; `b` is never evaluated.

The IR layout is:
```
and.entry:
  br i1 %lhs, label %and.rhs, label %and.merge
and.rhs:
  <evaluate b>
  br label %and.merge
and.merge:
  %result = phi i1 [ false, %and.entry ], [ %rhs, %and.rhs ]
```

**Bug fixed**: `current_block_` is a member variable that persists across function codegen boundaries. If the previous function ended with a `when_end` block, `current_block_` would still hold `"when_end784"` when the next function started. Using `current_block_` as the phi predecessor would reference a block from a different function — LLVM verification error `use of undefined value '%when_end784'`.

**Fix**: emit a fresh `and.entry`/`or.entry` block label via `br label %and.entry` + `and.entry:` before saving the phi predecessor. This guarantees the predecessor is always within the current function's scope.

LLVM's optimizer folds the 2-block phi back to a single `and i1` / `or i1` at O2 when both operands are pure (no side effects), so release-mode performance is identical to the eager form.
