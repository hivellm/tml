## Summary

Extended phase24c's `Heap.into_raw()` workaround from the Typedef
arm to the three remaining tag-ref arms in
`compiler-tml/src/cc/types.tml::base_to_ctype`:

- `StructRef(tag)` — `struct Foo` references
- `UnionRef(tag)` — `union Bar` references
- `EnumRef(tag)` — `enum Baz` references

End-to-end `tml cc` now parses C sources that use `struct`, `union`,
or `enum` tags as function parameters:

```c
struct Point { int x; int y; };
int sum(struct Point a, struct Point b) { return a.x + b.x; }
```

```c
union Variant { int i; float f; };
int test(union Variant v) { return v.i; }
```

```c
enum Color { RED, GREEN, BLUE };
int test(enum Color c) { return c == RED; }
```

All three exit 0 with `cc_driver: parsed`.

## Pattern

```tml
StructRef(tag) => {
    if env.structs.has(tag) {
        var borrowed: Heap[CAggregate] = env.structs.get(tag)
        let raw: *CAggregate = borrowed.into_raw()
        return CType::Struct(Heap[CAggregate]::from_raw(raw))
    }
    ...
}
```

`borrowed.into_raw()` nulls the local's `ptr` so its drop hits the
`if this.ptr != null` guard and skips `mem_free`.
`Heap[CAggregate]::from_raw(raw)` reconstructs a fresh Heap holding
the same pointer; this Heap is moved into `CType::Struct(h)` and
will eventually drop with the returned CType, freeing the
allocation. The env's bucket Heap also still holds the pointer and
will try to free at env drop. Compile-time `tml cc` tools exit
before env drops fire, so the duplicate free is unobservable in
practice.

## Open: nested-Heap typedef expansion (phase24e to file)

`./build/debug/cc_driver.exe compiler/runtime/core/essential.c
-I compiler/runtime/include/c-stdlib --emit=ast` still segfaults at
exit 139. Bisect: `#include <signal.h>` alone reproduces the crash.
Root cause is the same Heap-borrow-drop bug class but at the
nested level — `__sighandler_t` typedef expands to
`Ptr(Heap[Func(Heap[CFuncType])])`. `t.get()` copies the outer
CType including the nested Heap pointer. The Typedef arm fix
neutralizes the OUTER local's drop but doesn't touch the nested
Heap's drop. When the returned CType drops, its inner Heap drops,
freeing the inner allocation that env's bucket CType also
references. Subsequent typedef lookups read the stale inner
pointer → SIGSEGV.

Surgical fixes:
- `into_raw()` on every nested Heap before returning — invasive
  and fragile.
- Deep-clone via `Heap.duplicate()` — requires `Duplicate` for
  CType + nested types (CType is recursive — needs careful
  derive).

Structural fix (the one-true-fix):
- Refcounted `Heap[T]` — `mem_free` gated by `refcount == 0`. Each
  `t.get()` increments. Each drop decrements. No surgical
  workarounds needed anywhere.
- Or change `HashMap` to store/return non-owning views for
  Heap-valued maps.

Next session: phase24e to either (a) deep-clone via `@auto(duplicate)`
on CType + family, or (b) prototype Rc-style Heap[T].
