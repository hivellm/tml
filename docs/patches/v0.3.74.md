# v0.3.74 — Session-scoped, stable-key incr.bin + IR-store GC (phase42a, F-020..F-026)

**Date:** 2026-07-18

## Summary

The ADR-002 red-green incremental cache paid full cost and almost never paid
off: `incr.bin` was loaded/merged/rewritten **once per test file** (O(N²) I/O),
`CodegenUnitKey` embedded the test's suite *position* (`test_entry_index`) so
adding/removing/reordering one file turned every sibling RED, the compiler build
hash was the DLL **mtime** (every relink wiped the cache), and the `ir/` store
was never garbage-collected. Net: the incremental layer mostly added I/O.

phase42a makes it a real cross-run cache. Measured on `core/hash` (14 units)
with the rebuilt compiler:

| | before (per findings) | after |
|---|---|---|
| GREEN-hit rate (warm, unchanged) | ≈ 0% | **100% (14/14)** |
| GREEN-hit rate (one file touched) | ≈ 0% (whole suite RED) | **93% (13/14, only touched unit RED)** |
| incr.bin I/O per suite | load+rewrite **per file** | **loads=4, saves=1** |
| `ir/` store | never GC'd (2.2 GB at measurement) | bounded to working set, GC'd at teardown |

Determinism gate: **28/28 targets at/above floor** (10 runs, adversarial).
Clean-suite parity, zero divergence: core/hash 14/14, compiler/borrow 12/12,
std/json 23/23. (core/alloc `sync_*` timeouts are the unrelated phase27d
`mut ref I64` regression from a concurrent session, not this change.)

## Changes

- **F-020 — session-scoped load.** `get_shared_prev_session()` returns one
  shared, read-only `PrevSessionCache` per run (memoized by path+mtime); every
  per-file `QueryContext` shares the one parsed copy instead of re-reading
  `incr.bin`. The O(N²) read churn (~13 GB read + 13 GB write per full suite)
  collapses to ~O(total). (Write side was already batched per-suite in 41c.)

- **F-023 — key stability.** `test_entry_index` and `has_cached_library_state`
  removed from `CodegenUnitKey` identity. The position-dependent IR bits — the
  `s{id}_` internal-symbol prefix (AST path) and the `tml_test_N` entry wrapper
  (both paths) — now derive from a **file-stable** id
  (`stable_test_symbol_id(file_path)`); the NDJSON dispatcher declares/calls the
  same stable symbol (new `DispatcherTestInfo::symbol_id`, `index` kept for
  --list / --test-index / event mapping) and the pre-link entry check uses it.
  `has_cached_library_state` moved into the session `options_hash` partition.
  A suite membership change no longer REDs sibling files.

- **F-024 — content-based build hash.** `compiler_build_hash()` is now the
  CRC32C of the compiler DLL/EXE *content*, streamed once and memoized in a
  `<binary>.bhash` sidecar keyed by (mtime,size). No-op relinks that reproduce
  identical bytes keep the cache GREEN; behavior-changing relinks invalidate.

- **F-025 — config partitioning.** Cache files are `incr.<options_hash>.bin`
  (with the cached-library-state bit folded into `options_hash`);
  `prune_incr_partitions` keeps the newest 4 and removes the legacy `incr.bin`.
  Alternating configs no longer mutually evict.

- **F-021 — aging, not a cliff.** The hard `entry_count > 10000` load rejection
  (a silent total reset) is replaced by session-recency aging at save
  (`write(max_entries)`, cap 100k, current-session entries first).

- **F-022 — IR-store GC.** `gc_ir_store()` deletes `ir/*` not referenced by any
  surviving key; run once at teardown from the final on-disk partitions (safe
  after parallel per-suite writes). The GREEN path no longer re-saves the IR/libs
  it just loaded. The v2→v3 format bump orphans all old v2 IR, reclaimed on the
  first v3 teardown.

- **F-026 — source-fingerprint memo.** `fingerprint_source()` is memoized
  process-globally, gated on (mtime,size), so unchanged stdlib/.meta sources are
  hashed once per run (~1,339× → 1×). Benefits both `compute_library_env_fingerprint`
  and GREEN ReadSource re-verification.

- **F-019 — telemetry.** `IncrTelemetry` counts GREEN/RED, incr.bin load/save
  count+time, and ir/ GC bytes; a per-run summary is logged at teardown.

**Cache format:** `INCR_CACHE_VERSION_MAJOR` 2→3 (CodegenUnit key no longer
serializes `test_entry_index`/`has_cached_library_state`). Old v2 caches are
rejected on load and regenerate once — expected and harmless.
