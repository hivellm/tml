# v0.2.15 — TML Self-Hosting Frontend Integration (phase13d)

**Date:** 2026-04-10

## Highlights

- **TML frontend is now the default parser** — `tml build`, `tml run`, and `tml test` all use the TML self-hosting lexer/parser by default (phase13d switchover)
- **C++ parser fallback** — `--stage=parser:cpp` forces the C++ frontend on all three commands
- **Zero regressions** — 213/213 compiler tests pass; same 27 pre-existing K001/T056 failures in core tests
- **0.9% compile overhead** — TML frontend adds <1% overhead vs C++ baseline (49592ms vs 49150ms for 50 stdlib modules)
- **Seven codegen fixes landed** — required to make the self-hosting parser work end-to-end

## Compiler

### TML Self-Hosting Frontend (phase13d)

The TML self-hosting lexer+parser (`main_frontend.exe`) is now the default compilation frontend:

- **`tml build <file.tml>`** → uses TML lexer/parser (was C++ by default)
- **`tml run <file.tml>`** → uses TML lexer/parser (was C++ by default)
- **`tml test`** → test compilation uses TML parser (was C++ by default)
- **Fallback**: `--stage=parser:cpp` forces C++ lexer/parser on all three commands

The hybrid pipeline (`--stage=<name>:<impl>`) now accepts both `"tml"` and `"cpp"` as valid `<impl>` values:

```bash
tml build myfile.tml                    # TML frontend (default since v0.2.15)
tml build myfile.tml --stage=parser:cpp # Force C++ frontend
tml test lib/core/tests --stage=parser:cpp  # Test with C++ parser fallback
```

### CLI Changes

- **`BuildOptions::stage_overrides`** defaults to `{{"parser", "tml"}}` (was empty map)
- **`RunOptions::stage_overrides`** defaults to `{{"parser", "tml"}}` (was empty map)
- **`TestOptions::stage_overrides`** new field, propagated from `--stage=` flag
- **`TestConfig::stage_overrides`** new field, propagated to `CompileConfig`
- **`CompileConfig::stage_overrides`** new field, propagated to `QueryOptions`
- Validation accepts `"cpp"` as an alternative to `"tml"` in `--stage=<name>:<impl>`

## Architecture

### Phase 13 Self-Hosting Timeline

- **phase13b**: TML self-hosting lexer (tokenizes `.tml` source files in pure TML)
- **phase13c**: TML self-hosting parser (parses TML modules, produces serialized binary AST)
- **phase13d** (this release): Integration — TML frontend wired as default pipeline stage

### Implementation Details

The TML frontend operates as a subprocess: `main_frontend.exe <source.tml>` writes a binary-serialized `Module` AST to stdout. The C++ host reads and deserializes it via `serial::read_ast()` in `query_core.cpp`. The `--stage=parser:tml` → `--stage=parser:cpp` fallback uses the existing `stage_overrides` map in `QueryOptions`.
