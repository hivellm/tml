# v0.3.60 — Move dataflow activated + staged strict-moves flag (phase26f 1.1-1.2)

**Date:** 2026-07-16
**Phase:** phase26f (Move-Semantics Activation Milestone) — items 1.1 + 1.2 only
**ADR:** ADR-009 (B1-on-AST) · rulebook decision #12

## Summary

The NLL borrow checker's full-move dataflow had been **dead code since
inception**: `BorrowChecker::move_value()` / `move_projection()` were the sole
writers of `OwnershipState::Moved` / `moved_projections` and were **never
called** — so `moved_out` in the exported ownership facts (phase26b Step 2.1,
v0.3.57) was uniformly false and blatant use-after-move (`let y = x; use(x)`)
compiled clean. This release **activates the dataflow** and stages a
use-after-move policy behind a flag, **without changing any default behaviour**.

## Item 1.1 — Activate the move dataflow

Move recording (`move_value` / `move_projection`) is now wired at the real move
sites in the checker's walkers:

| Site | Location |
|---|---|
| let-init from identifier (`let y = x`) + partial (`let leaf = base.field`) | `checker_stmt.cpp` `check_let` |
| by-value function argument (honours `ref`/`mut ref` params via `lookup_func`) | `checker_expr.cpp` `check_call` |
| by-value method argument (receiver stays a borrow) | `checker_expr.cpp` `check_method_call` |
| struct field init + `..base` update | `checker_expr.cpp` `check_struct_expr` |
| enum-payload / constructor args (`Just(x)`) | via `check_call` (no free-func sig ⇒ by-value) |
| `return` of a local | `checker_expr.cpp` `check_return` |
| `x = y` (RHS moved) | `checker_expr.cpp` `check_binary` |

**Type threading (prerequisite).** The checker's places were created with
`nullptr` type, so `is_copy_type` treated *everything* as copy — no move could
ever be classified. The type checker now records each `IdentPattern`'s resolved
type against the existing `expr_types_` map (`types/checker/stmt.cpp`
`bind_pattern`, covering let bindings and function params), and the borrow
checker threads it back into the place (`check_let`, `check_func_decl`). Move
classification is `is_move_type = !is_copy_type` (primitives incl. `Str`,
references, tuples/arrays thereof, and `Copy`-derived named/class types are
copies; owning collections, smart pointers and plain value structs move).

**Correctness cautions honoured.** Method receivers are borrows (two-phase),
never moves. `.duplicate()`/`.get_clone()` results are `MethodCallExpr`, not
bare identifiers, so they never move their subject. `ref x` / `mut ref x` are
`UnaryExpr`, so they stay borrows. Reassignment after move re-initialises the
place (`check_binary`). `drop_scope_places` preserves the terminal `Moved`
state (a moved-out value is not dropped again) so the fact survives to the
end-of-function snapshot.

## Item 1.2 — Staged use-after-move policy + blast radius

All move-derived diagnostics (use / borrow / assign / move after move, in
`checker_ops.cpp`, `checker_nll.cpp`, `checker_expr.cpp`) are gated behind
`TML_STRICT_MOVES=1` (read once at construction). **Default OFF:** `Moved` is
recorded so ownership facts carry signal, but no diagnostic is emitted — zero
behaviour change vs. the pre-phase26f checker. **ON:** use-after-move becomes a
hard `B001` (Rust-strict).

**Blast radius** (`TML_STRICT_MOVES=1`, full details in
`.rulebook/tasks/phase26f_move-semantics-milestone/specs/blast-radius/spec.md`):

- **176 files compiled → 7 files (4.0%) / 53 move errors.**
- **~96% idiomatic implicit-copy of value types** (would-migrate, not bugs):
  `Layout` reused by value dominates (42 errors, 4 alloc files — Rust's
  `Layout` is `Copy` but the TML type has no derive); small value structs
  `Point`/`Interval` reused after by-value pass/arg; raw pointers reused.
- **1 genuine latent bug**: `scripts/fixtures/double_free_probe.tml` deliberate
  double-free — exactly the target class.
- **Classifier gaps recorded (not fixed):** `PtrType` should be Copy; trivially
  copyable value structs should be auto-/derived-Copy (this alone is ~92% of
  the radius); method-arg param-kind is unresolved in the checker (bare-ident
  method args conservatively moved).

## Verification

- **Join-proof** (`TML_DROP_FACTS_DEBUG=1`, `--legacy`): `let y = x` now emits
  `[DROP-JOIN] … var=x … moved_out=1 consumed=0 … DISAGREE-payoff` — the fact
  the syntactic `consumed_vars_` set missed (acceptance for 1.1).
- `refcount_bleed_probe.tml`: all facts `moved_out=0` (no bare-ident moves), no
  false positives; `tml run` still exit 0.
- **Flag OFF regression:** determinism gate **22/22** (adversarial ON);
  core/alloc 44/44, core/str 32/32, std/json 23/23, std/collections 19/19
  (pre-existing `arraylist` K001 unchanged, owned by phase27a).

## Scope

Items 1.3–1.7 (drive drop suppression from `moved_out`, remove
`consumed_vars_`, drop-flag elaboration, migrate the value-type `Copy`
fallout, final gates) are **deferred** — not started in this release.
