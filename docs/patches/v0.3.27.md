# v0.3.27 — Rust Parity: AVX-512 List Iteration

**Date:** 2026-04-15

## Summary

Closes the 13× performance gap between TML and Rust for `for x in list` iteration.
With `@inline` on iterator methods and compile-time constant stride, LLVM now fully
vectorizes pointer-stepping loops with `<8 x i64>` AVX-512 instructions.

## Benchmark (100M I64 single-pass sum, release)

| Language | Ops/sec | Time |
|----------|---------|------|
| **Rust** (rustc 1.93, O2) | ~4.4B | 21ms |
| **TML** (0.3.27, O2) | ~3.7B | 26ms |
| **Ratio** | **1.18×** | — |

Both are memory-bandwidth limited at this scale. The optimized IR shows identical loop
structure: 5-instruction scalar loop and `<8 x i64>` SIMD with 4 accumulators (32
elements per iteration).

## Changes

### Performance

- **`@inline` on `into_iter()`, `iter()`, `next()`** — LLVM now inlines the full iterator
  protocol, enabling:
  - mem2reg promotion of all allocas to SSA phi nodes
  - Constant propagation of stride (compile-time `8` for I64)
  - Full LoopVectorizer activation → `<8 x i64>` AVX-512

- **Compile-time constant stride** — `gen_for_pointer_stepping` now emits constant stride
  for primitive types (i8=1, i16=2, i32/f32=4, i64/f64/ptr=8) instead of loading from
  the ListIter struct. Falls back to runtime stride for struct element types.

- **Fixed `List.iter()` struct mismatch** — `iter()` was returning a 4-field struct
  `{ handle, len, stride, index }` that didn't match `ListIter`'s 3-field definition
  `{ ptr, end, stride }`. Now uses the same pointer-stepping setup as `into_iter()`.

### Optimized IR (after LLVM O2)

Inner scalar loop (matches Rust exactly):
```llvm
pstep.body:
  %ptr   = phi ptr [ %next, %pstep.body ], [ %init, %preheader ]
  %total = phi i64 [ %new, %pstep.body ], [ 0, %preheader ]
  %val   = load i64, ptr %ptr, align 8
  %new   = add nsw i64 %val, %total
  %next  = getelementptr inbounds nuw i8, ptr %ptr, i64 8  ; constant stride!
  %done  = icmp eq ptr %next, %end
  br i1 %done, %exit, %pstep.body
```

SIMD vector loop (32 elements per iteration):
```llvm
vector.body:
  %wide.load   = load <8 x i64>, ptr %p0, align 8   ; elements 0-7
  %wide.load.1 = load <8 x i64>, ptr %p1, align 8   ; elements 8-15
  %wide.load.2 = load <8 x i64>, ptr %p2, align 8   ; elements 16-23
  %wide.load.3 = load <8 x i64>, ptr %p3, align 8   ; elements 24-31
  ; 4 independent <8 x i64> accumulators for pipeline parallelism
```
