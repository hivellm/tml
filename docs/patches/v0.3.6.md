**Date**: 2026-04-14

## Performance — `switch` optimization for `when` expressions (phase0d)

### Summary

Integer `when` expressions with 4+ literal arms now emit a single LLVM `switch`
instruction instead of a cascading `icmp eq` + conditional branch chain.

### Benchmark results

| Benchmark | Before | After | Rust |
|-----------|--------|-------|------|
| When Dense (10 cases) | ~9.5 ns/op (icmp chain) | <1.5 ns/op (switch) | <1.5 ns/op |
| When Sparse (10 cases) | ~9.5 ns/op (icmp chain) | <1.5 ns/op (switch+btree) | <1.5 ns/op |

TML/Rust ratio: 1:1 (parity achieved).

### Technical details

**File**: `compiler/src/codegen/llvm/control/when.cpp`, `gen_when()`

**Eligibility criteria** (all must hold):
- Scrutinee type is an integer (`i1`, `i8`, `i16`, `i32`, `i64`)
- At least 4 arms have integer or bool literal patterns (`kMinSwitchArms = 4`)
- No arm has a guard condition
- No `OrPattern` arms

**Generated IR** (before):
```llvm
%t1 = icmp eq i64 %x, 0
br i1 %t1, label %when_arm0, label %when_next0
when_next0:
%t2 = icmp eq i64 %x, 1
br i1 %t2, label %when_arm1, label %when_next1
; ... 8 more comparisons
```

**Generated IR** (after):
```llvm
switch i64 %x, label %when_end [
  i64 0, label %when_arm0
  i64 1, label %when_arm1
  ; ... 9 more entries
]
```

LLVM's `switch` lowering selects jump tables for dense ranges and binary search
trees for sparse ranges — both are significantly faster than linear icmp chains.

### Regression test

`compiler/tests/compiler/when_switch_dense.test.tml` — 6 tests covering dense,
sparse, minimal (4 arms), bool scrutinee, default arm, and wildcard-as-default.

### No regressions

- Core test suite: 769/808 pass (39 pre-existing failures unchanged)
- Compiler test suite: 286/290 pass (4 pre-existing K001/method failures unchanged)
- Switch path gated on `is_int_scrutinee` — enum/string/struct `when` unaffected
