# Patch Notes v0.2.0–v0.2.9

---

## v0.2.0 — 2026-03-19

## Summary

Major release. Query-based incremental compilation, embedded LLVM/LLD (50x test speedup), THIR layer, Polonius borrow checker, 35+ new stdlib modules, async network stack with HTTP/2 + WebSocket, and comprehensive runtime migration away from C.

---

## Highlights

- **Query-Based Compilation** — Demand-driven pipeline (like rustc) with cross-session incremental caching via Red-Green fingerprint coloring. Near-instant rebuilds when source is unchanged.
- **Embedded LLVM + LLD** — In-process IR-to-object compilation and linking. Zero subprocess spawning. Full test suite: ~15 min → ~17 seconds (50x improvement).
- **Zig CC as Default Compiler** — Zig CC (Clang 20.1.2 + bundled LLD) replaces MSVC for building the TML compiler itself.
- **THIR Layer** — Typed HIR between type checking and MIR with advanced trait solver, numeric coercion insertion, and pattern exhaustiveness checking.
- **Polonius Borrow Checker** — Alternative Datalog-style borrow solver (`--polonius`); strictly more permissive than NLL.

---

## Added (Standard Library — 35+ new modules)

- **`std::http`** — Full HTTP/1.1 server and client with radix-tree router, TLS, cookies, multipart, middleware
- **`std::crypto`** — SHA-1/256/512, AES-GCM, ChaCha20-Poly1305, RSA, ECDSA, Ed25519, X.509 certs, DH/ECDH key exchange
- **`std::zlib`** — Deflate, Gzip, Brotli, Zstd compression/decompression
- **`std::sqlite`** — SQLite3 FFI bindings with prepared statements and typed rows
- **`std::regex`** — Thompson's NFA regex engine with capture groups
- **`std::search`** — BM25 full-text search + HNSW approximate nearest-neighbor vector search
- **`std::aio`** — Async I/O event loop (epoll on Linux, WSAPoll on Windows), timer wheel
- **`std::stream`** — Composable async streams with backpressure, buffering, piping
- **`std::math`**, **`std::datetime`**, **`std::os`**, **`std::glob`**, **`std::random`**

- **Smart pointers** — `Heap[T]` (Box), `Shared[T]` (Rc), `Sync[T]` (Arc) with full Drop/Clone

## v0.2.4 — 2026-03-25

## Summary

Developer tooling and research infrastructure release: the `--debug-layers` flag exposes HIR, MIR, and LLVM IR on test failure to dramatically shorten the debugging loop, the MCP call logger provides NDJSON telemetry for LLM tool-use research, and diagnosis hints automatically identify which compilation layer likely contains a bug.

---

## Added

### Compiler — Debug Tooling

- **`--debug-layers` flag for `tml test`** — On any test failure, automatically emits the HIR, MIR, and LLVM IR for the failing test functions alongside the error message. Eliminates the need to manually run `tml emit-ir` and cross-reference output when debugging codegen failures.

- **`--emit-hir` flag for `tml build`** — Emits the High-level IR (HIR) to a `.hir` file alongside the object output. Useful for verifying that desugaring, monomorphization, and type resolution produced the expected intermediate representation.

- **`MIR print_function_by_name`** convenience function — Extract and pretty-print a single MIR function by name without printing the entire module. Used internally by `--debug-layers`.

- **Diagnosis hints** — `generate_diagnosis_hints()` analyzes the error message and IR content to suggest which compilation layer (parser, type system, HIR builder, codegen, runtime) is the likely source of a bug. Hints are printed below the IR output in debug-layers mode.

### MCP Infrastructure

- **MCP call logger** — All MCP tool invocations are logged in NDJSON format to `mcp-call-log.jsonl`. Each entry records: tool name, parameters (without output content), timestamp, duration, session ID, and experiment condition. Implemented using C `FILE*` for Windows compatibility (avoids C++ stream issues with concurrent writes).

- **`debug_layers` parameter on MCP `test` tool** — Enables `--debug-layers` mode directly from MCP clients without needing to modify CLI invocations.

- **`TML_DEBUG_LAYERS=1` env var** — Toggles debug-layers as the default in the MCP test tool, enabling A/B experiment conditions (baseline vs. debug-layers always on) without code changes.

- **`TML_MCP_LOG_DIR` env var** — Override the directory where `mcp-call-log.jsonl` is written. Useful for routing logs to a shared location in team or research setups.

### Documentation

- **`docs/user/ch13-04-debug-layers.md`** — User guide explaining the debug-layers feature, what each layer shows, and how to interpret the diagnosis hints.

- **`docs/papers/llm-ir-debugging/`** — Research paper structure for studying LLM-assisted debugging through multi-layer IR exposure. Includes introduction, methodology, experimental design, and results sections.

- **`docs/papers/llm-ir-debugging/scripts/analyze_logs.py`** — Analysis script for the MCP call log. Features: session labeling, A/B condition comparison, Welch's t-test, Cohen's d effect size, and tool transition heatmaps showing which tools LLMs use after a failure.

## v0.2.5 — 2026-03-26

## Summary

Compiler correctness release targeting codegen bugs that caused segfaults and heap corruption, plus eight new OOP reflection intrinsics, a substantial documentation coverage push to 91.4%, and a new user guide for the reflection system.

---

## Fixed

### Compiler — Codegen

- **MIR print type dispatch** — `println(42)` and similar calls segfaulted because the MIR path was emitting `@println(i32 42)` instead of the type-specific `@print_i32(i32 42)`. Added correct dispatch for all primitive types.

- **Missing static method arguments** — `List[T]::new()` crashed on Win64 because the call was emitted with 0 arguments, but the definition expected 1 (initial_capacity). The codegen now fills in default arguments when they are absent.

- **Template literal support** — MIR path now handles template literals natively via inline `to_string` (snprintf). No legacy codegen fallback is required.

- **Nested struct shallow copy / heap corruption** — `List.push(report)` followed by scope exits freed shared List handles prematurely. Fixed by marking struct arguments as consumed and suppressing field drops for let-bindings that originate from method calls.

- **Missing enum type definitions** — `RefCell__I32` referenced `%struct.BorrowState`, but that enum type was never emitted. The compiler now auto-emits referenced enum types from the module registry.

- **Non-lazy stdlib for tests** — The pre-compiled stdlib now includes all public library functions rather than lazily including only what was referenced. This eliminates a class of linker errors in test executables.

- **`dso_local` on all declarations** — Added `dso_local` to all function declarations to prevent LLVM 23+ from merging function declarations with similar signatures across translation units.

---

## Added

### Compiler — Reflection Intrinsics

Eight new OOP reflection intrinsics for class inspection:

- **`is_abstract[T]()`** — returns `Bool` indicating whether `T` is an abstract class.
- **`is_sealed[T]()`** — returns `Bool` indicating whether `T` is sealed.
- **`base_class[T]()`** — returns the name of `T`'s base class as a `Str`, or empty if none.
- **`method_count[T]()`** — returns the number of methods defined on `T`.
- **`method_name[T](i)`** — returns the name of the i-th method.
- **`is_virtual[T](i)`** — returns `Bool` for whether the i-th method is virtual.
- **`is_override[T](i)`** — returns `Bool` for whether the i-th method overrides a base method.
- **`is_static_method[T](i)`** — returns `Bool` for whether the i-th method is static.

Supporting infrastructure:

- **`ClassMeta`** populated during `gen_class_decl` with method names and virtual/override/static flags.
- **`MethodInfo`** type in `core::reflect` — name, is_virtual, is_override, is_static.
- **`InterfaceInfo`** type in `core::reflect` — name, method_count, has_parents.
- **`TypeInfo::for_class`** factory function plus `is_class()` and `method_count()` methods.
- **`to_json[T: Reflect]`** in `std::debug` — JSON-like serialization of any reflected type for debugging output.

### Documentation

- **`docs/user/ch15-00-reflection.md`** — Complete user guide for the reflection system, covering TypeInfo, field introspection, method introspection, and serialization.

### Research

- **Condition B activation** — `--debug-layers` now defaults to ON in the MCP test tool for organic data collection on LLM IR debugging behavior. Controllable via `TML_DEBUG_LAYERS` env var.

## Changed (Test System)

- **Per-test watchdog timeout increased 100ms → 20s** — The previous 100ms cap caused SIMD-heavy tests and any test with non-trivial computation to be killed by the watchdog. The limit is now 20 seconds per individual test (tests annotated `@slow_test` get 10,000ms as before — now effectively unlimited for practical purposes).

- **60-second hard cap on test process lifetime** — Every test executable is unconditionally killed after 60 seconds regardless of suite size or per-test settings. Prevents any single process from hanging indefinitely.

- **Cache directory consolidation** — The three previously separate cache locations no longer exist. All cache artifacts now live under `build/debug/cache/`:
  - `build/debug/cache/` — runtime archive (`tml_test_runtime.lib`), compiled test EXEs, object files (was `.test-cache/` + `.new-run-cache/`)
  - `build/debug/cache/tests.json` — persistent test result cache (was `.new-test-cache.json`)
  - `build/debug/cache/incr/` — incremental codegen fingerprint cache (was `.incr-cache/`)

- **Fail-fast shows full error output** — When a test fails, the subprocess is killed immediately and the complete error message is shown without truncation. Previously output was capped at 20 lines.

- **1 EXE per test file (default)** — `suite_mode` is now `false` by default. Each `.test.tml` file compiles to its own EXE, giving precise per-file isolation and cache granularity. Previously the default was to group up to 8 files per EXE.

- **Fully parallel compilation** — Compile workers now use all available hardware threads (was `hw/2`). The `num_threads` override that was hardcoded to 1 in the coordinator is removed. Up to 8 test EXEs are compiled simultaneously and logged individually as they complete (e.g. `[compile] Building foo.exe (3/40)` / `[compile] OK foo.exe 341ms (3/40)`).

- **Fail-fast across all phases** — Fail-fast now stops the run at the first compile error or test failure, across all pipeline phases:
  - Compile workers set `should_stop` immediately on error; remaining workers in the same batch abort.
  - The batch loop checks `should_stop` before starting each new batch and exits early.
  - The execution phase is skipped entirely if `should_stop` is set after compilation.
  - The terminal reporter shows `ABORTED: stopped on first error (fail-fast)` instead of bogus counts.

- **Fixed false-positive compile error counts** — When fail-fast triggered mid-run, the coordinator previously counted all pre-allocated-but-never-attempted suite slots as compile errors (up to 1783 phantom errors). Now only suites that were actually attempted are counted.

- **`tml_test_runtime.lib` relocated** — The shared runtime archive is now stored at `build/debug/cache/tests/tml_test_runtime.lib` alongside the compiled test EXEs, instead of at `build/debug/cache/` root.

- **Staging `.obj` files deleted after link** — Temporary object files (per-file `.obj` + dispatcher `.obj`) are removed immediately after the test EXE is successfully linked. Persistent compiled EXEs remain in `cache/tests/` as before.

- **Timestamped test logs** — `--verbose` now writes to `build/debug/logs/test_YYYYMMDD_HHMMSS.json` instead of overwriting a single `test_log.json`. After each run the timestamped file is also copied to `build/debug/test_log.json` as a "latest" pointer for tooling compatibility.

- **Rich compile error diagnostics** — Compile errors now include `file:line:col: [CODE] message` with full source location. Previously only the bare message was stored. Notes attached to errors are also shown. Cascading (redundant) type errors are suppressed to reduce noise. When a file has multiple errors all are logged, not just the first.

- **Reporter cleanup** — The `Suites:` line is removed from the summary (no longer meaningful with 1 EXE/file). `Tests:` and `Passed:` are hidden when no tests ran (compile-error-only or full fail-fast abort), avoiding misleading zero counts.

- **MCP test `diagnostics` field** — `mcp__tml__test` with `structured=true` now returns a `diagnostics[]` array containing the full error text (ANSI-stripped, JSON-escaped) for every compile error and test failure, including `file:line:col` location and indented error detail lines. Previously only bare test names were returned in `failures[]`.
