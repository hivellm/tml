# v0.3.48 — Eliminate residual SIGSEGV in cc_driver parenthesized declarator path (phase24h)

**Date**: 2026-05-03
**Branch**: `feat/self-hosting-compiler`
**Task**: phase24h_cc-funcptr-typedef-sigsegv

## TL;DR

`cc_driver` previously SIGSEGV'd non-deterministically (50–80% of runs)
on any C declaration that went through a parenthesized inner-declarator
or function-pointer typedef:

```c
int (*p);
typedef void (*sig_t)(int);
typedef void (*tml_panic_hook_fn)(const char*);
```

This patch closes the bug class by giving `CDeclarator` an explicit
`Duplicate` impl and inserting `.duplicate()` at the two partial-field-
move sites in `cp_parse_direct` and `cp_parse_declarator_inner`. All
four minimal repros now exit 0 in 30/30 runs (was ~16/30). `cc_driver`
on `essential.c` now parses past the function-pointer typedef block
(line 170-173) and advances to the next downstream blocker at line
189:43 (a real parse error, not a crash).

## Root cause

`CParsedDeclarator` is `{ decl: CDeclarator, pos: I64 }`. The parser
extracts the declarator with a partial-field move:

```tml
let Ok(inner) = inner_res else { ... }
leaf = inner.decl                    // partial move out of `inner`
p = np
// `inner` falls out of scope here — TML's auto-generated drop runs
```

`CDeclarator::Pointer` and friends contain `Shared[CDeclarator]` (a
refcounted handle). Without an explicit `Duplicate` impl on `CDeclarator`,
the partial-field move bitwise-copies the variant payload — so both
`leaf` (which gets returned wrapped in a new variant) and the source
`inner.decl` (which is dropped along with `inner`) point at the same
`Shared` allocation. The first drop decrements to 0 and frees; the
second drop decrements to -1 and writes through the freed pointer →
non-deterministic crash depending on whether the allocator has
recycled the slot.

The same pattern appears in `cp_parse_declarator_inner`:

```tml
let Ok(direct) = direct_res else { ... }
var d: CDeclarator = direct.decl    // partial move out of `direct`
// loop wraps d with Pointer layers
return Ok(CParsedDeclarator { decl: d, pos: direct.pos })
// `direct` drops here, double-free on its dropped `decl`
```

The parenthesized path (`int (*p);`) routes through `cp_parse_direct`'s
inner recursion AND the outer `cp_parse_declarator_inner`, so both
partial-move sites fire — explaining why parenthesized declarators
crashed at higher rates than `int *p;`.

## Fix

Two surgical changes:

1. **`compiler-tml/src/cc/ast.tml`** — manual `impl Duplicate for
   CDeclarator` (because `@auto(duplicate)` doesn't yet support enums).
   Each variant arm forwards to `Shared::duplicate()` (cheap refcount
   bump) and `Maybe::duplicate()` / `Heap::duplicate()` for non-Shared
   payloads. Also added `@auto(duplicate)` to `CFuncDeclPart`.

2. **`compiler-tml/src/cc/parser.tml`** — replaced the two partial-
   field-move sites with explicit `.duplicate()`:

   - `cp_parse_direct` line 1246: `leaf = inner.decl` →
     `leaf = inner.decl.duplicate()`
   - `cp_parse_declarator_inner` line 1338: `var d = direct.decl` →
     `var d = direct.decl.duplicate()`

   `.duplicate()` on a `CDeclarator` containing `Shared` payloads is
   essentially `refcount += 1` per variant — the source `inner.decl`
   stays valid for the source struct's drop, and the new `leaf` /
   `d` owns its own count.
