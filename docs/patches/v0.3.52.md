# v0.3.52 — Codegen-level structural fix for Shared/HashMap/List.get aliasing class (phase24n)

**Released:** 2026-05-05
**Branch:** `feat/self-hosting-compiler`
**Task:** [phase24n_cc-preproc-aliasing-sweep](../../.rulebook/tasks/phase24n_cc-preproc-aliasing-sweep/)

## Why

`HashMap[K, V]::get(k)` and `List[V]::get(i)` returned a bitwise alias of the slot value. When `V` contained nested refcount-shared handles (`Shared[T]`, `Heap[T]`, `Str`, transitive aggregates), the alias's drop decremented refcounts that the source slot still expected to own — frees ran twice and the next probe of the container hit freed memory.

Phase24k diagnosed the bug class. Phase24l added an opt-in `Shared.get_clone` and migrated one `cc/preproc` site (typedef arm). Phase24m landed 15+ surgical `.duplicate()` calls across the rest of `cc/preproc`. Both whittled the symptom but did not close it: ~30+ aliasing sites remained across `cc/`, and even the surgical sweep was reactive to one symptom path at a time.

This release attacks the root cause at the codegen layer instead. The fix lives entirely in the TML compiler — `lib/std/collections/hashmap.tml::get`, `get_opt`, and `lib/std/collections/list.tml::get` swap `ptr_read[T]` for the new intrinsic `ptr_read_clone[T]`, and every downstream consumer (`cc/preproc`, `cc/parser`, user code, future libraries) inherits the safe semantics without further intervention.

## What Changes

### New intrinsic: `ptr_read_clone[T](ptr) -> T`

Same-shape sibling of `ptr_read[T]` but with auto-cloning semantics:

| Case | Behaviour |
|------|-----------|
| `T` is primitive (i1/i8/i16/i32/i64/i128/f32/f64/ptr) | Bitwise load only — duplicate is identity, elided. |
| `T` is an aggregate with a manual `impl[U] Duplicate for X[U]` (e.g. `Shared`, `Heap`, `Box`, `Rc`, `Arc`) | Bitwise load → `alloca` spill → `X::duplicate(spill)` call → return duplicated value. |
| `T` is a struct/enum with `@derive(Duplicate)` / `@auto(duplicate)` | Same load+spill+call pattern. The intrinsic also drives `gen_derive_duplicate_struct` and queues the duplicate via `pending_impl_method_instantiations_` so the function is emitted into the IR. |
| `T` is a pure-POD aggregate without any Duplicate impl (e.g. `CQualifiers`) | Falls back to bitwise read — preserves `ptr_read` semantics. |

The bitwise temp (`%spill_prc.<N>` in MIR codegen, `%t<N>` in AST codegen) is a transient alloca whose inner refcounted handles still belong to the source slot. It is deliberately NOT registered for drop — only the duplicated result, which carries its own bumped refcounts, is consumed by the caller.

### Codegen sites

- **AST path (legacy)**: `compiler/src/codegen/llvm/builtins/intrinsics.cpp` — handler appears immediately after `ptr_read`. Detection uses `struct_decls_`, `pending_generic_structs_`, `pending_generic_enums_`, `pending_generic_impls_`, and `pending_generic_impls_all_` to verify `Duplicate` is available before emitting the call. Mangling via `mangle_impl_method`.
- **MIR path (default)**: `compiler/src/codegen/mir/instructions_call.cpp::emit_intrinsic_ptr_read_clone`. Mirror of the AST emission with a local `mangle_itanium_path` helper and a `canonical_module_for_type` table mapping known library types (`Shared`, `Heap`, `Box`, `Rc`, `Arc`, `Cell`, `RefCell`, `List`, `HashMap`, `HashSet`, `Buffer`, `Maybe`, `Outcome`, `Str`) to their module paths so the duplicate symbol resolves at link time.
- **Intrinsic table**: `compiler/src/codegen/intrinsic_table.cpp` + `compiler/include/codegen/intrinsic_table.hpp` register `IntrinsicKind::PtrReadClone` so the MIR dispatcher routes to the new emitter.

### Lib changes

- `lib/std/src/collections/hashmap.tml`: `get(this, key) -> V` and `get_opt(this, key) -> Maybe[V]` now use `ptr_read_clone[V]` for the user-visible value load (the internal `ptr_read[I64]` / `ptr_read[I8]` reads of header fields and control bytes stay bitwise — those are primitives and would be no-ops anyway).
- `lib/std/src/collections/list.tml`: `get(this, index) -> T` uses `ptr_read_clone[T]`.
- `lib/core/src/alloc/shared.tml::get_ref` (introduced in phase24l) is preserved as the borrow-only alternative for callers that want to inspect the inner value without taking ownership.

## Bug Class Architecture

This fix continues the structural-over-surgical pattern established by phase24g:

- **phase24g**: `Heap[T]` (unique-owning) → `Shared[T]` (refcount-shared) for cc AST nodes. Eliminated heap-borrow-drop in declarator chain.
- **phase24l**: `Shared.get_clone(this) -> T where T: Duplicate` opt-in deep-clone API.
- **phase24m**: 15+ surgical `.duplicate()` calls in cc/preproc (preserved by phase24n).
- **phase24n** (this release): codegen-level auto-clone in `HashMap.get` / `List.get` via `ptr_read_clone[T]` intrinsic. Eliminates the bug class for every consumer of the canonical container getters.

## Compatibility

No source-level breaking changes. `Shared.get` semantics unchanged (still bitwise — callers that need deep-clone use `Shared.get_clone`). `HashMap.get` / `List.get` semantics unchanged in observable behaviour for primitive `V`/`T` (bitwise was already correct); for non-primitive `V`/`T` the returned value now has fresh refcounts which is the correct behaviour but slightly heavier — measure once, then inline `T::duplicate` at LLVM `-O2`.

## Limitations / Follow-ups

1. essential.c × 5 = 0/5 SIGSEGV remains. Different bug class, separate task scope.
2. MIR `canonical_module_for_type` is a static table for known library types. New refcounted libraries need a one-line entry. Long-term: thread the type registry through to MIR codegen so the MIR path can look up modules dynamically.
3. The intrinsic emits `gen_derive_duplicate_struct` for non-generic struct types directly to work around the early-return in `gen_struct_decl` when types are pre-registered by `runtime_modules.cpp`. A cleaner future fix is to move the derive emission out of `gen_struct_decl` into a separate pass that runs after pre-registration.
4. `Shared.get` itself is unchanged (uses `(*this.ptr).value` which is a struct field load via deref+access, NOT `ptr_read`). Callers needing deep-clone still call `Shared.get_clone()` explicitly. Adding auto-clone to `Shared.get` requires a different codegen hook.
