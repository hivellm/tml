# v0.3.82 — phase26g: collection mutators `mut this` + full get_ref-then-mutate detection

**Date:** 2026-07-19
**Task:** `phase26g_collection-mutator-mut-this` (user decision #13: Rust-style
mutability over the `@invalidates_refs` attribute)
**Branch:** `fix/era0-stabilization`

Completes the interior-reference safety story started in phase26e:
`get_ref`-then-mutate is now a **B009 compile error on all four collections**.

## Mutator signature migration

- Flipped to `mut this`: **List** (20 mutators: push/pop/set/clear/insert/
  remove/swap_remove/extend/reserve/truncate/dedup/fill/resize/reverse/swap/
  retain/drain/sort/sort_by/split_at + internal sorts), **HashMap** (8),
  **Buffer** (8 write-side ops). **BTreeMap, Deque, HashSet/Queue/Stack/Vec/
  LinkedList were already `mut this`.** Reads stay `this`.
- **Measured surprise — no call-site cascade:** calling a `mut this` mutator
  on an owned `let` binding compiles in this compiler (receiver mutability is
  not enforced against owned bindings), so the feared 20+ test breakage did
  not materialize and no `let`→`var` migration was needed. NOTE for the
  record: this means binding-level mutability visibility (the Rust-style
  `var` requirement) is NOT yet enforced by the type checker — the safety
  payoff below comes from the borrow checker. Enforcing `var` for `mut this`
  receivers would be a separate type-checker decision.

## Borrow-checker completion (the payoff)

- The phase26e wiring computed `recv_is_mut_this` and **discarded it** —
  fixed: a `mut this` mutator call now takes a transient unique borrow that
  conflicts with any live interior-ref borrow (B009). Plus a false-positive
  fix: refs consumed inline (`let x: I64 = *c.get_ref(i)`) no longer leave a
  phantom borrow.
- **`Maybe[ref V]` propagation:** `ref_kind_in_type` detects refs carried in
  generic wrappers; `check_when` binds the `Just(r)` payload to the receiver
  borrow for direct method-call scrutinees; and `LetElseStmt` — previously
  **entirely unvisited** by the borrow checker — is now checked
  (`check_let_else`), binding `let Just(r) = m.get_ref(k) else` the same way.
  Plain `Maybe[V]` (get_opt) manufactures no borrow.
- Result: `let r = l.get_ref(0); l.push(x); use(*r)` rejects on List/Deque;
  the `when`/`let-else` forms reject on HashMap/BTreeMap.
  `compiler/tests/cli/borrow_interior_ref.sh` **6/6** negative fixtures;
  positive NLL shapes (mutate after last use, read-only in arm + mutate
  after, get_opt) all green. Blast-radius sweep: **zero** new borrow errors
  across collections/alloc/json/hash/http samples + stdlib self-builds.
