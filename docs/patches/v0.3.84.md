# v0.3.84 — phase44b: std/collections standalone heap corruption

**Date:** 2026-07-20
**Task:** `phase44b_collections-standalone-heap-corruption`
**Branch:** `fix/era0-stabilization`

The three std/collections tests that failed standalone-only after phase44a
lifted the harness false-pass — `deque_extras`, `deque_extras2`, `iter_ref` —
are now green. They were **three independent bugs**, not one, and the unifying
"clone-read and drop must be symmetric" hypothesis from the task header held
only for one of them; the other two were a plain arithmetic error and a library
aliasing bug.

## Root causes

**1. `deque_extras2` — `Deque::rotate_left`/`rotate_right` arithmetic (library).**
Both only adjusted `this.head`. Live elements occupy slots
`[head, head+length) mod capacity`, so advancing `head` alone slides that window
onto `steps` slots that hold no element — correct only when `capacity == length`.
Not memory corruption at all; a return-code rewrite failed deterministically
(exit 14, `dq.get(4)` wrong after `rotate_left(2)`).

**2. `deque_extras` — `DequeIter` aliased the backing buffer (library).**
`Deque::iter()` built its iterator with a bitwise `data: this.data`, so the
iterator and the deque owned the *same* `List[T]` buffer and both dropped it →
double-free / use-after-free (`INVALID FREE: DDDDDDDDDDDDDDDD` under poison).
The receiver-clone-read the task hypothesized does not exist and could not work:
`List` is **move-only** (`Drop`, no `Duplicate`), so a structural duplicate of it
is a shallow handle copy. The sibling owning iterators `HeapIter`/`BTreeMapIter`
already build a fresh, logically-ordered snapshot and drop it correctly.

**3. `iter_ref` — `when`-arm binding drop skipped for temporary scrutinees (codegen).**
The genuine codegen bug. The clone-read bump in `ListIter::next()` was never
balanced because a `when`-arm binding extracted from an enum scrutinee was
unconditionally skipped for drop (`when.cpp` guard `if (!scrutinee_is_enum)`).
That guard is correct only for a **named** enum variable (whose payload the
scrutinee itself drops later). For a **temporary** enum scrutinee — a call /
method-call result like `when it.next() { Just(row) => … }` — IR confirmed
neither the `Maybe` temp nor `row` was ever dropped, so the arm binding is the
sole owner of the moved-out/clone-read payload and must drop at arm exit.
Deterministic exit-23 leak (`h.strong_count()` never returning to 2).

## Fix

- `lib/std/src/collections/deque.tml` — `rotate_left`/`rotate_right` move
  elements via `pop_front`/`push_back` (resp. `pop_back`/`push_front`) instead
  of sliding `head`; `DequeIter::iter()` builds an owned snapshot (`List[T]`,
  allocate + push copies) like `HeapIter`/`BTreeMapIter` — non-consuming
  iterator, independent buffer, balanced drop.
- `compiler/src/codegen/llvm/control/when.cpp` — `gen_when` now computes
  `scrutinee_is_temporary` (Call/MethodCall) and registers the arm binding for
  drop when it holds. `register_for_drop` already no-ops for non-droppable
  payloads, so the blast radius is bounded to handle-bearing owned payloads.

A third, tempting codegen-only "suppress move-only field drops at the let site"
fix was implemented and then **reverted**: it would leak `HeapIter`/`BTreeMapIter`
(genuine owners of a `List` snapshot), which are indistinguishable from
`DequeIter`'s alias at the let-binding site — only the library knows which is an
owner. The alias had to be fixed in the library.

Suite-packed mode: all deque/iter files pass with zero crash/corruption; the
only remaining failure is a load-induced watchdog TIMEOUT that **floats**
between unrelated tests (`buffer_core`, then `drop_btree_debug` — both pass
standalone, neither touches Deque/iterators), i.e. the pre-existing floating
flaky, not introduced here. The change strictly improves suite-packed mode
(`deque_extras` went crash → pass).

Methodological note: the earlier "receiver clone-read" framing (task 1.3b/1.3c)
was disproven by IR tracing — the by-value receiver is passed by pointer with no
clone-read. Two of the three failures were library bugs; only one was codegen.
