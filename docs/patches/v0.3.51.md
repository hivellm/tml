# v0.3.51 — phase24j: CBlockItem / CStmt / CExpr / CInit migrated to `Shared[T]`

## Summary

Continues the structural Heap → Shared migration started in phase24g (which
covered `CType`, `CDecl`, `CDeclarator`, `CTypeEnv` buckets) into the rest
of the C-frontend AST: every `Heap[CExpr]`, `Heap[CStmt]`, `Heap[CBlockItem]`,
`Heap[CInit]`, `Heap[CTypeName]` payload across `compiler-tml/src/cc/{ast,
parser,lower}.tml` is now `Shared[T]`. Mirrors the phase24h pattern: explicit
`.duplicate()` on every partial-field move site (~70 sites) plus manual
`impl Duplicate for CExpr / CStmt / CBlockItem / CInit / CDesignator /
CInitElement / CGenericAssoc / CTypeName` (the `@auto(duplicate)` derive
does not yet support enums with recursive `Shared` payloads).

## Why

Pre-phase24j: `cc_driver compiler/runtime/core/essential.c` × 5 → 0/5 SIGSEGV
(deterministic, exit 139), residual from the same Heap-borrow-drop bug class
that phase24g/24h closed for declarators. `Heap[CBlockItem]` /
`Heap[CStmt]` / `Heap[CExpr]` were the last major Heap-bearing AST layers.

## Files modified

- `compiler-tml/src/cc/ast.tml` (+154/-19) — Shared variants on `CExpr`,
  `CStmt`, `CBlockItem`, `CInit`, `CDesignator`, `CGenericAssoc`,
  `CDeclarator::Array.size`, `CVarDecl.init`, `CFuncDecl.body`,
  `CEnumVariantDef.value`, `CDecl::StaticAssert`. Manual
  `impl Duplicate` for every migrated enum + free helpers
  (`dup_designator_value`, `dup_block_item_value`, `dup_block_items`,
  `dup_init_elem_value`, `dup_init_elems`, `dup_designators`,
  `dup_shared_expr_list`, `dup_generic_assocs`) that route around two
  codegen ABI bugs:
  1. Auto-derived `List[T].duplicate` for small enum element types
     (e.g. `CDesignator = {i32, i64}`) emits the per-element call as
     `call ... (ptr %val)` while the manual impl receives by value.
  2. Auto-derived `List[Shared[T]].duplicate` mis-types the per-element
     `Shared.duplicate()` return as `Shared[Shared[T]]` instead of `Shared[T]`.
- `compiler-tml/src/cc/parser.tml` (+~70 explicit `.duplicate()` /
  `Shared::new` swaps) — every construction site for Shared variants and
  every partial-field move that escapes its source local now copies via
  `.duplicate()` to keep the source's drop refcount-safe.
- `compiler-tml/src/cc/lower.tml` — `for_rest` signature updated
  (`Maybe[Heap[CExpr]]` → `Maybe[Shared[CExpr]]`).

## Residual — essential.c × 5 still 0/5

Despite the structural migration, `compiler/runtime/core/essential.c`
(1465-line file with `setjmp`/`longjmp`, complex preprocessor expansion,
deeply nested function bodies, large global arrays) still SIGSEGVs at
exit 139 in cleanup. Empirical observations:

- The pipeline gets through preprocessing and parsing successfully on
  many runs (no `cc_driver: parse failed` log written).
- The crash is deterministic for `essential.c` specifically; smaller
  multi-feature C programs (200 globals, deeply nested control flow,
  function-pointer typedefs) all exit 0.
- Subset bisection: `essential.c` truncated to 250-300 lines also crashes
  intermittently — the trigger is content-shape, not file size.

The remaining bug is most likely an interaction between (a) many globals
of a complex shape (`enum TmlCrashSeverity` discriminant + `static
volatile int32_t` initializers + `static char[N] = {0}` aggregates),
(b) parsed CExpr trees with deeply nested `Comma` / `Assign` / `Cond`
chains, and (c) the auto-derived `List[CBlockItem].duplicate` codegen on
the function-body Compound paths that we have not yet hand-rolled.

Filed as follow-up: **phase24k_essential-cleanup-segv**. phase0z gate
(essential.c × 5 → 5/5) remains active; phase24j ships as partial fix.

## Pattern note for future migrations

Manual `impl Duplicate for SmallEnum` (where the enum lays out as a few
words like `{i32, i64}`) hits a calling-convention codegen mismatch when
called through the auto `List.duplicate` path. The work-around in
phase24j is a free function `dup_<list_t>(src) -> List[T]` that writes
out the loop by hand and either calls `.duplicate()` on element types
that the codegen handles correctly (e.g. `Shared[T]`) or invokes a
free helper `dup_<element>_value(v) -> T`. This sidesteps the dispatch
bug at the cost of one helper per problematic element type.
