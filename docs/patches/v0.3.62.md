# v0.3.62 — Fact-driven drop suppression (union with consumed_vars_) (phase26f 1.3)

**Date:** 2026-07-16
**Phase:** phase26f (Move-Semantics Activation Milestone) — item 1.3
**ADR:** ADR-009 (B1-on-AST) · rulebook decision #12

## Summary

The payoff of the phase26b borrow-fact foundation. AST-codegen drop suppression
is now driven by the borrow checker's now-live `moved_out` facts (exported
v0.3.60, made reliable v0.3.61), **unioned** with the pre-existing syntactic
`consumed_vars_` set. This closes a real double-free class: a plain `let b = a`
let-init is NOT marked in `consumed_vars_` (there is no `mark_var_consumed` at the
let-statement handler) but IS reported `moved_out` by the checker — so before this
release both `a` and `b` were dropped at scope exit, decrementing a shared handle
twice under a live independent owner.

## The swap is a UNION, not a replacement

`consumed_vars_` is **retained** (not retired). The method-arg safe-fallback
(v0.3.61) means `moved_out` deliberately UNDER-reports: by-value method arguments
are unresolvable in the checker (no method resolution) so they are tracked only
syntactically. Suppression therefore fires when **either** signal reports the
binding consumed:

- **Syntactic side (`consumed_vars_`):** covers by-value method args via the ~30
  `mark_var_consumed` sites — `destroy()`, function/enum/struct-init args,
  `return`, assignment, `when` bindings. This is the method-arg blind spot the
  fact under-reports.
- **Fact side (`ownership_by_span_[def_span].moved_out`):** span-keyed (so it
  distinguishes shadowed bindings a bare-name key cannot), projection-aware,
  checker-authoritative. ADDS the precise ident moves the syntactic sites miss —
  notably plain `let b = a`.

Implemented as `LLVMIRGen::drop_suppressed_by_move(const DropInfo&)`
(`compiler/src/codegen/llvm/core/drop.cpp`), called at both scope-exit sites
(`emit_scope_drops`, `emit_all_drops`).

**What the facts caught that `consumed_vars_` missed:** the let-init
double-drop. A new probe (`scripts/fixtures/let_move_double_drop_probe.tml`)
proves it directly:

```
let witness = Shared::new(42)   // count 1
{
    let a = witness.duplicate() // count 2
    let b = a                   // MOVE: a moved_out (consumed=0, moved_out=1)
}                               // block exit: only b drops → count 1
if witness.strong_count() != 1 { exit 1 }
```

- **Before this release:** `witness.strong_count()` returns **0** — `a` and `b`
  both dropped (2→1→0), the control block freed under the live `witness`.
- **After:** returns **1** — `a`'s drop is suppressed by the move fact, only `b`
  drops.

Registered in `scripts/determinism-corpus.txt` as the `tml_let_move_double_drop`
user-path canary (runs via `tml run` — the AST codegen path where the class
manifests; the query/MIR test-framework path masks it, per ADR-009).

## Partial (projection) moves

Partial moves stay on the existing syntactic `"var.field"` prefix scan
(`has_consumed_fields`). The exported `PlaceOwnershipFact` carries only the
monotonic whole-place `moved_out` (granularity (i)); `moved_projections` is
deferred to phase26b Step 4, so there is no fact-side partial signal to union in
yet. Noted in-code at both suppression sites.

## Scope note — `consumed_vars_` retirement deferred

The wiring plan's Step 5 ("retire the ~30 `mark_var_consumed` sites + remove
`consumed_vars_`") is **deferred to the method-resolution follow-up**, not done
here. Retiring them now would drop the method-arg blind-spot coverage that
`moved_out` cannot yet provide. The `tasks.md` text for item 1.3 is updated to
reflect the union design and the deferral.
