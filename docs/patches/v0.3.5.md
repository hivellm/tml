# v0.3.5 — 2026-04-14

## Fixed

### N002: Crypto C Runtime Files Failing to Link

Programs using `std::crypto`, `std::net::tls`, or any module that transitively depends
on the OpenSSL C runtime files now compile and link correctly.

**Root cause**: `find_openssl()` Tier 0 (vcpkg) check found OpenSSL but did not set
`include_dir` from the vcpkg path. This caused `ensure_c_compiled()` to invoke
`zig-cc.bat` with `-I""` (empty include path), failing to find `<openssl/sha.h>` and
other OpenSSL headers. On failure, the fallback returned raw `.c` source paths
(e.g. `compiler/runtime/crypto/crypto.c`), which LLD rejected as "unknown file type".

**Fix**: Set `result.include_dir` from the vcpkg installation path in
`builder_helpers.cpp:find_openssl()` Tier 0 block. The compile command now includes
`-I"<project_root>/vcpkg_installed/x64-windows/include"` and all 9 crypto C files
compile to valid `.obj` files on first run.

**Also fixed**: `run_profiled.cpp` (profiled `tml run --time` path) was missing the
OpenSSL library additions to link flags. Added the same OpenSSL `.lib` + `/DEFAULTLIB`
block that `builder_run.cpp` uses.

**Affected modules**: `std::crypto` (8 C files), `std::net::tls` (1 C file) — ~42% of
standard library modules that depend on OpenSSL (crypto, TLS, HTTP, networking).

**Verified**:
- Fresh compilation produces all 9 `.obj` files in `build/debug/deps/`
- `benchmarks/profile_tml/crypto_bench.tml` runs SHA-256/SHA-512/MD5 benchmarks
- `benchmarks/profile_tml/large_scale_bench.tml` runs 100K socket bind benchmark
- `lib/std/tests/crypto/hash.test.tml` (35+ tests) passes
- No regressions: core 50/50, std 20/20
