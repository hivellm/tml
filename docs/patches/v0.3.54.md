# v0.3.54 — LLVM Verifier as Hard Error on Every Emission Path (phase25b)

**Date:** 2026-07-15 · **Branch:** `fix/era0-stabilization` · **ERA 0 Stabilization, Plan Phase A3**

Invalid LLVM IR can no longer land silently. Before this patch the verifier ran
on only ONE of three emission paths (`compile_ir_to_object`), only AFTER the
optimization pipeline, and demoted failures to a warnings-vector entry that
nothing surfaced. `compile_ir_to_buffer` — the in-process-link path used by
normal builds — and the ORC JIT **never verified at all**.

## Changes

- `compiler/src/backend/llvm_backend.cpp`: shared `verify_module_or_fail`
  policy helper. `LLVMVerifyModule` now runs **pre-optimization** (invalid IR
  fed to `LLVMRunPasses` is undefined behavior — a suspected X003 source) and
  **post-optimization** (optimizer-interaction bugs) on BOTH the object-file
  and in-memory-buffer paths. Failure = hard error `[K002] Module verification
  failed (<phase>): <verifier message>`; no object is produced.
- `compiler/src/backend/jit_engine.cpp`: `llvm::verifyModule` before
  `addIRModule` — verifier-invalid IR never reaches JIT execution.
- Escape hatch for bisection only: `TML_NO_VERIFY_IR=1` demotes to a warning.
- `tml explain K002` rewritten (was "verification warning"; now documents the
  hard-error policy, the phase labels, and the escape hatch).
- `scripts/known-failures.txt`: tracked known-failures manifest (K001 / X002 /
  X003 / determinism floors, one owning task per line, shrink-only policy) —
  the boundary between known debt and new regression.
- 3 gtest regressions in `compiler/tests/foundational/llvm_backend_test.cpp`
  (dominance-violating IR — parses, only the verifier rejects). Note:
  `tml_tests` currently fails to configure under Zig CC (googletest
  `cxx_std_14` compile-feature detection; pre-existing, MSVC-era binary) —
  tests are in-tree for MSVC builds.

## Fallout measurement (behavioral validation)

209 compiler suites + determinism corpus + core/alloc + std/json recompiled
with `--no-cache` under the hard-error verifier: **zero K002 occurrences,
zero regressions** — the verifier introduces no false positives on real IR.
Sole failure: a test-coordinator duplicate-scheduling race (same suite built
twice in one batch; N001 on the deleted .obj; suite passes alone) — recorded
in the known-failures manifest as flaky infra.

## Impact

Any codegen change that produces structurally invalid IR now fails the build
at the exact phase that introduced it, with the offending function named —
protecting every fix phase27a will land.
