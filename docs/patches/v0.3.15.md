## Summary

The TML compiler DLLs can now be built in Release mode, providing a **2.93×
speedup** for individual compilations. A new `TML_COMPILER_BUILD=release` env
var lets the debug `tml.exe` use the optimised release DLLs without changing
PATH or rebuilding the launcher.

---

## Benchmark Results

| Mode | Single-file compile | Speedup |
|------|--------------------|---------| 
| Debug DLLs | 6.899s | — |
| Release DLLs | 2.358s | **2.93×** |
| Full test suite (188 tests, cold) | 100.3s → 81.6s | 1.23× |

The 2.93× per-file improvement exceeds the ≥2× benchmark gate. The test
suite speedup is lower (1.23×) because LLVM backend object emission and
LLD linking (done per-test in separate child processes) are not affected by
the compiler DLL build type — those processes load their own LLVM. The
single-file speedup reflects the compiler's own LLVM initialization and
IR-generation phases.

The `<50ms` total compile gate requires a persistent daemon (phase0n) to
keep the DLL loaded between compilations. LLVM static initializers (~2.4s
release, ~6.9s debug) dominate cold-start time regardless of build type.

## Implementation

### 1. `scripts/build.bat release` already existed

The build script already supported `release` as a positional argument
(sets `-DCMAKE_BUILD_TYPE=Release`). CMakeLists.txt already applied `/O2`
(MSVC) and `-O3 -fomit-frame-pointer` (Zig CC/Clang) for non-Debug configs.
No changes needed to the build system itself.

### 2. `Loader::discover_paths()` — env var overrides

`compiler/src/plugin/loader.cpp` `discover_paths()` now honours two env vars:

```cpp
// TML_PLUGIN_DIR — explicit override (was in error messages but not implemented)
const char* plugin_dir_env = std::getenv("TML_PLUGIN_DIR");
if (plugin_dir_env && plugin_dir_env[0]) {
    plugins_dir_ = fs::path(plugin_dir_env);
    return;
}

// TML_COMPILER_BUILD=release — redirect to build/release/bin/plugins/
const char* build_override = std::getenv("TML_COMPILER_BUILD");
if (build_override && std::string(build_override) == "release") {
    auto build_dir = exe.parent_path().parent_path(); // build/debug → build/
    auto release_bin_plugins = build_dir / "release" / "bin" / "plugins";
    if (fs::exists(release_bin_plugins)) {
        plugins_dir_ = release_bin_plugins;
        return;
    }
    // warn + fall through to debug if release not found
}
```

### 3. Clang `-Wdate-time` pragma in `query_incr.cpp`

Release mode with Zig CC (Clang 20) treats `-Wdate-time` as an error.
`query_incr.cpp` uses `__DATE__`/`__TIME__` as a last-resort fallback hash
for the incremental compilation cache on platforms without `/proc/self/exe`.
Added `#pragma clang diagnostic ignored "-Wdate-time"` around the fallback
section.

## Usage

```bash
# Build the release compiler once
scripts\build.bat release

# Use the release compiler for all subsequent tml commands
set TML_COMPILER_BUILD=release
tml build myfile.tml
tml test --suite=mymodule
```
