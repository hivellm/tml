# v0.3.43 — phase24e (partial): CType deep-clone via impl Duplicate

**Date**: 2026-05-02
**Branch**: `feat/self-hosting-compiler`
**Task**: phase24e (deep-clone via Duplicate)

## Summary

Replaced phase24c/24d's `into_raw` + `from_raw` workaround with a
proper deep-clone path via `Duplicate`:

- Added `@auto(duplicate)` to: `CFuncType`, `CArrayType`,
  `CAggregateField`, `CAggregate`, `CEnumValue`, `CEnumType`.
- Wrote manual `impl Duplicate for CType` covering all 24 variants
  (the recursive enum `Heap[CType]`-bearing variants make
  hand-rolling clearer than fighting auto-derive on enums).
- `base_to_ctype` Typedef arm: `t.get().duplicate()` builds an
  independent CType; `t.into_raw()` still neutralizes the local
  Heap's drop so the bucket retains ownership.
- StructRef / UnionRef / EnumRef arms: `borrowed.duplicate()` on
  the bucket Heap produces a fresh allocation; `borrowed.into_raw()`
  neutralizes the local borrow's drop. Returned CType variant owns
  an independent allocation, not aliasing the bucket.

Effect: every CType returned from `base_to_ctype` is now a deep
independent copy. Bucket and consumer are fully decoupled — no
double-free hazard regardless of drop order.

## Open: function-pointer typedef declaration crash

`echo 'typedef void (*sig_t)(int);' | tml cc` exits 127 silently.
The crash is on the typedef DECLARATION (no use of the typedef
yet), so it's not in `base_to_ctype`'s lookup path. Likely in
`apply_declarator`'s Pointer arm where it builds `CType::Ptr(Heap
[CType::Func(Heap[CFuncType])])`. The recursion + Heap-wrapping
chain may have a different drop-glue issue.

Bisect for next session:
- `apply_declarator` Pointer arm: drops `base_ty` (parameter,
  passed by value) on exit. If `base_ty` is `Void`, drop is
  harmless; but the chain `Func(Heap[CFuncType])` constructed
  via apply_declarator's Func arm has nested Heaps that may
  share allocations with returned CType payloads.
- `apply_declarator` Func arm builds CFuncType { ret: Heap[CType],
  params: List[Heap[CType]] }; the `params` list might trigger a
  copy-vs-move bug.
