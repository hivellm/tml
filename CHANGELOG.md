| [0.3.52](docs/patches/v0.3.52.md) | 2026-05-05 | **Codegen-level structural fix for `Shared/HashMap/List.get` aliasing class (phase24n)** — adds new intrinsic `ptr_read_clone[T]` to TML codegen (`compiler/src/codegen/llvm/builtins/intrinsics.cpp` + MIR equivalent in `compiler/src/codegen/mir/instructions_call.cpp`). When `T` has a non-trivial `Duplicate` impl (manual `impl[T] Duplicate for X[T]` for refcount-shared `Shared` / `Heap`, OR `@derive(Duplicate)` / `@auto(duplicate)` on a struct/enum with nested handles), `ptr_read_clone` performs a bitwise load and emits an explicit `T::duplicate(temp)` call so the returned value carries fresh refcounts; the bitwise temp is a transient alloca that is NOT registered for drop. For primitive `T` (i1/i8/i16/i32/i64/i128/f32/f64/ptr) the duplicate is identity — no extra IR is emitted. `lib/std/src/collections/hashmap.tml::get`/`get_opt` and `lib/std/src/collections/list.tml::get` now use `ptr_read_clone[V]`/`ptr_read_clone[T]` instead of `ptr_read`, eliminating the entire bug class structurally — every consumer (`cc/preproc`, `cc/parser`, user code, library code) gets the fix automatically without per-site `.duplicate()` calls. Detection is conservative: only types with verified `Duplicate` impl get auto-clone (verified via `pending_generic_impls_` for manual impls, `@derive`/`@auto` decorators on `struct_decls_` / `pending_generic_structs_` / `pending_generic_enums_` for derived impls). Pure POD aggregates without a Duplicate impl fall back to bitwise read. The fix also queues `T::duplicate` for lazy instantiation via `pending_impl_method_instantiations_` and drives `gen_derive_duplicate_struct` for non-generic library types whose pre-registration in `runtime_modules.cpp` skipped derive emission. Gates preserved: `c_essential_repro.c` × 30 = 28/30 (matches phase24m baseline); `sig_alone.c` × 30 = 30/30; `int_p.c` × 30 = 30/30. `essential.c` × 5 remains 0/5 — that residual SIGSEGV is a separate parser-level state aliasing bug class that this codegen fix does NOT close (filed as follow-up). lib/core regressions documented in PLANS.md (cache_aligned_box, future_fuse, types_encoding, time, etc.) verified pre-existing — same failures appear when stashing all phase24n changes and rebuilding HEAD. New regression test: `compiler/tests/compiler/get_deep_clone.test.tml`. |
