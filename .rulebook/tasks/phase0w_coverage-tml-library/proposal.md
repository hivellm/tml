# Proposal: build a TML-native coverage library at `lib/coverage/` and wire `tml coverage` to it

## Why

TML's current coverage subsystem lives entirely inside the C++ compiler:
about 3,350 lines of C/C++ spread across `compiler/src/testing/testing_coverage.cpp`
(1,153 LOC), `compiler/src/testing/testing_coverage_html.cpp` (1,397 LOC),
`compiler/src/cli/commands/cmd_coverage.cpp` (412 LOC), `lib/test/runtime/coverage.c`
(388 LOC) and a thin façade in `lib/test/src/coverage.tml` (126 LOC).

This has three practical problems:

1. **Wrong substrate.** HTML is generated by string-concatenating
   `<div>`/`<style>`/`<script>` literals in C++ — 1,397 lines that cannot
   be iterated on without recompiling the compiler. The C++ code also
   re-implements file-tree aggregation, percentage rounding and
   presentation logic that would be ~10x shorter in a high-level
   language.
2. **Proprietary format.** The collector writes
   `.sandbox/coverage-*.json` in a shape nothing else consumes — no
   Codecov, no Coveralls, no VS Code Coverage Gutters, no `genhtml`.
3. **Violates ADR-006 (TML-First Runtime).** The runtime piece
   (`lib/test/runtime/coverage.c`) and the reporting pipeline are all
   in C/C++ despite being pure text/JSON/HTML work with no LLVM API
   needs.

Meanwhile, TML's own language and standard library are mature enough
to do all of this (`lib/core/src/str/*`, `lib/core/src/io/*`,
`lib/std/src/json/*`, `lib/std/src/collections/*`, `lib/chart/` as a
working precedent for HTML emission) in pure `.tml`. The rebuild is
the right time to move the reporting layer out of C++ and into a
first-class TML library.

The architectural analysis at `docs/analysis/coverage/` mapped the
market, surveyed the state of the art, and recommended LLVM
source-based coverage as the collection backbone with a static HTML
SPA as the reporter. That recommendation split the work across two
concerns: **(a) codegen-side instrumentation** (emit
`llvm.instrprof.increment`, link `compiler-rt` profile runtime) and
**(b) reporting-side ingestion, merging, HTML emission**. This task
owns (b). (a) is a separate, codegen-scoped task that can land in
parallel or after this one.

Source: `docs/analysis/coverage/` (README + 5 deep-dive files).

## What Changes

This task creates `lib/coverage/` — a new TML library — and rewires
the `tml coverage` CLI command to dispatch to it. The library owns
every stage of the reporting pipeline: parsing raw coverage files,
merging parallel-test results, computing summaries, and emitting LCOV,
JSON and HTML output.

### CLI changes

`compiler/src/cli/commands/cmd_coverage.cpp` becomes a ~150 LOC
dispatcher: it collects the raw coverage files produced by
`tml test --coverage`, resolves the `lib/coverage` module via the
workspace, builds or reuses a `coverage_cli.exe` binary whose `main`
calls `coverage::run(args)`, and forwards stdin/stdout/exit-code.

The contract between the C++ CLI and the TML library is a small
argv subset:

```
coverage_cli.exe
  --input=<path-or-glob>    (required; accepts `.lcov`, `.json`, `.profraw`, dir)
  --format=lcov|json|html|cobertura|all
  --output=<dir>            (default `./coverage-report`)
  --include=<glob>          (repeatable)
  --exclude=<glob>          (repeatable)
  --baseline=<path>         (optional; for delta reporting)
  --fail-under=<pct>        (exit 2 if overall coverage < pct)
```

### Public TML API (`lib/coverage/src/mod.tml`)

```tml
// Ingest
func read_lcov(path: Text) -> Outcome[CoverageReport, IngestError]
func read_llvm_json(path: Text) -> Outcome[CoverageReport, IngestError]
func read_legacy_json(path: Text) -> Outcome[CoverageReport, IngestError]
func read_dir(path: Text) -> Outcome[CoverageReport, IngestError]

// Transform
func merge(reports: List[CoverageReport]) -> CoverageReport
func filter(r: CoverageReport, include: List[Text], exclude: List[Text]) -> CoverageReport
func summarize(r: CoverageReport) -> Summary

// Emit
func write_lcov(r: CoverageReport, path: Text) -> Outcome[(), EmitError]
func write_json(r: CoverageReport, path: Text, compact: Bool) -> Outcome[(), EmitError]
func write_html(r: CoverageReport, out_dir: Text) -> Outcome[(), EmitError]
func write_cobertura(r: CoverageReport, path: Text) -> Outcome[(), EmitError]

// Orchestration (entry point used by `tml coverage`)
func run(args: CliArgs) -> I32
```

### Input format support

Three parsers, picked by extension or magic bytes:

- **LCOV `.info`** (primary, since it is the universal ingest format)
- **`llvm-cov export -format=text` JSON** (primary forward-facing
  format — when the LLVM codegen migration lands, this is what the
  compiler will emit)
- **Legacy `.sandbox/coverage-*.json`** (transition-only, so the
  library works against the current collector while the codegen-side
  rebuild happens separately)

`.profraw` is **not** ingested directly in this task; running
`llvm-profdata merge` and `llvm-cov export` is a responsibility of
the CLI wiring (or a helper shelled out from `run()`), not the
library itself.

### Output formats

- `lcov` — LCOV `.info` for Codecov/Coveralls/SonarQube/GitHub
- `json` — compact JSON consumed by the HTML SPA
- `html` — static SPA at `<out_dir>/index.html` (works offline via
  `file://`); uses the JSON emitter as its data source
- `cobertura` — Cobertura XML for GitLab CI / Jenkins
- `all` — all of the above into `<out_dir>/{coverage.lcov, coverage.json, coverage.xml, index.html, ...}`

### Removed / deprecated

- `compiler/src/testing/testing_coverage_html.cpp` (1,397 LOC) —
  replaced by the new HTML emitter in TML. Deletion lands in **Phase 7**
  of this task's checklist after the TML HTML reporter reaches parity.
- The HTML-generation portion of `cmd_coverage.cpp` — thinned to a
  dispatcher.

## Acceptance criteria

After this task lands:

1. `lib/coverage/` exists with the layout above and imports cleanly
   (`tml check lib/coverage/src/mod.tml` succeeds).
2. `tml test --suite=coverage` runs all 10 test files and all pass.
3. `tml coverage --input=<existing legacy json dir> --format=all
   --output=./out` produces a non-empty `coverage.lcov`,
   `coverage.json`, `coverage.xml`, and `index.html` that renders
   without errors when opened via `file://`.
4. The produced LCOV opens in `genhtml` (external tool) and shows
   sensible per-file data.
5. The new HTML has file tree, per-file source view, line/branch
   counters, syntax highlighting for TML and C++, search, and works
   offline with no CDN.
6. `testing_coverage_html.cpp` is deleted; the `testing_coverage.cpp`
   HTML path is gone; the C++ CLI command is ≤250 LOC.
7. A regression test asserts that running `tml coverage` on a
   fixture legacy JSON produces byte-exact output against a golden
   LCOV file.

## Impact

- **Affected specs**: new spec at `.rulebook/tasks/phase0w_coverage-tml-library/specs/coverage/spec.md` capturing the SHALL/MUST contract for `read_*`/`write_*`/`merge`/`run`.
- **Affected code**: `lib/coverage/` (new, ~2,000 LOC of TML + ~500 LOC
  of template/HTML/JS/CSS); `compiler/src/cli/commands/cmd_coverage.cpp`
  (rewrite to dispatcher); deletion of `compiler/src/testing/testing_coverage_html.cpp`.
- **Breaking change**: No for TML-language users. The `tml coverage`
  CLI gains new flags (`--format`, `--baseline`, `--fail-under`)
  while keeping existing flags working. The on-disk report layout
  changes (`.sandbox/coverage-*.json` → `./coverage-report/*`),
  documented in the changelog.
- **User benefit**: HTML reporter becomes iterable without
  recompiling the compiler; LCOV/Cobertura/JSON output unlocks
  Codecov and every other SaaS; TML library code can be tested,
  profiled and refactored like any other TML module; the 1,397-line
  HTML-in-C++ blob disappears.
