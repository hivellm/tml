## Phase 1: Namespaces and Scoping (3 items)

- [ ] 1.1 Extend the C parser with namespace declarations: `namespace foo { ... }` introduces a new scope; `namespace foo::bar::baz { ... }` (C++17 nested namespace shorthand) desugars to nested scopes; implement anonymous namespaces `namespace { ... }` (linkage is internal, equivalent to `static` at file scope); extend `CParser` into `CppParser` that delegates C declarations to the C parsing infrastructure and handles C++-specific constructs in a new `parse_namespace_decl()` method
- [ ] 1.2 Implement `using namespace foo;` (unqualified name lookup searches namespace `foo`); `using foo::bar::Type;` (imports a single name into the current scope); `using Type = foo::bar::Baz;` (type alias, equivalent to typedef but more powerful); qualified name lookup `foo::bar::Baz` in expressions and type positions; track the lookup order: current scope → enclosing scopes → `using namespace` imports → global namespace
- [ ] 1.3 Implement argument-dependent lookup (ADL / Koenig lookup): when an unqualified function call `f(x)` is not found in normal lookup, also search the namespaces of the types of all arguments; ADL is required for operators (`operator<<`, `operator+`) and is used extensively in the STL; implement the set-of-associated-namespaces rule per C++17 §6.4.2

## Phase 2: Classes and Inheritance (5 items)

- [ ] 2.1 Implement class/struct declarations with access specifiers: `class Foo { private: int x; public: int y; };` (class defaults to private, struct to public); member function declarations inside the class body and out-of-class definitions `int Foo::method() { ... }`; `const` member functions `int get() const { ... }` (cannot modify non-mutable members); `static` member variables and functions; `this` pointer (implicit first parameter of non-static member functions, type `T*` or `const T*`)
- [ ] 2.2 Implement constructors and destructors: default constructor `Foo() {}`, parameterized constructor `Foo(int x) : x_(x) {}` with member initializer list; copy constructor `Foo(const Foo& other)`; move constructor `Foo(Foo&& other)` (C++11); copy assignment `Foo& operator=(const Foo& other)`; move assignment `Foo& operator=(Foo&& other)`; destructor `~Foo()`; implement the Rule of Five: if any of destructor, copy ctor, copy assign, move ctor, move assign is user-defined, the others are not implicitly declared; implement `= default` and `= delete` for special member functions
- [ ] 2.3 Implement single inheritance: `class Derived : public Base { ... }` (only public inheritance in the subset — private/protected inheritance is not supported); derived class contains all base class fields followed by its own fields; member function lookup checks derived class first, then base; `Base::method()` qualified call to bypass virtual dispatch; implement `override` keyword (verify that the marked function actually overrides a virtual base method); `final` keyword on class to prevent further derivation
- [ ] 2.4 Implement virtual dispatch: the vtable is a compile-time array of function pointers, one per virtual method in declaration order; each class instance begins with a hidden `vtbl_ptr` field pointing to the class vtable; a virtual method call `obj->method()` loads `vtbl_ptr`, indexes to the method's slot, and calls through the pointer; emit vtable as a constant global array; derived class vtable copies base vtable and overrides slots for overridden methods; `virtual ~Foo()` is common and must work correctly (destructor slot in vtable)
- [ ] 2.5 Implement `static` member variables (exist once per class, not per instance — emit as global with mangled name), `static` member functions (no `this` parameter — called as `Foo::method()`), `constexpr` member functions (evaluated at compile time for constant expressions), `mutable` member variables (can be modified even through `const` reference — used for mutexes and caches in `const` methods), `explicit` constructors (prevent implicit conversion from single-argument constructors)

## Phase 3: Templates (5 items)

- [ ] 3.1 Implement function templates: `template<typename T> T max(T a, T b) { return a > b ? a : b; }` — parse template parameter list, store the template as a `FunctionTemplate` (unevaluated AST + parameter list); implement template argument deduction: when `max(1, 2)` is called, deduce `T = int` from the argument types; explicit template arguments `max<double>(1, 2)` override deduction; emit an instantiation for each unique deduced/specified argument set
- [ ] 3.2 Implement class templates: `template<typename T, int N> class Array { T data[N]; ... };` — store as `ClassTemplate`; instantiate when first used: `Array<int, 10> arr;` → generate `Array_int_10` struct with field `data: [i32 x 10]`; name mangling for instantiations uses Itanium ABI mangling on Linux/macOS and MSVC-style mangling on Windows; class template member functions are themselves templates and are instantiated lazily
- [ ] 3.3 Implement template instantiation: on first use of a template with specific type arguments, perform substitution of template parameters with concrete arguments throughout the template body; re-typecheck the substituted body (SFINAE: if substitution fails, the template is not a candidate rather than an error); store already-instantiated templates in a cache keyed by `(template_id, args)` to avoid duplicate emission; instantiated class template methods are only instantiated if called (lazy instantiation)
- [ ] 3.4 Implement explicit template specialization: `template<> int max<int>(int a, int b) { ... }` (full specialization — overrides the primary template for `T=int`); partial specialization for class templates: `template<typename T> class Array<T*, 0> { ... }` (matches any pointer type with N=0); implement specialization ordering: more specialized templates are preferred; the primary template is selected only if no specialization matches
- [ ] 3.5 Implement non-type template parameters: `template<int N> class Buffer { char data[N]; };` — integer, enum, and pointer non-type parameters; `template<auto N>` (C++17 deduced non-type parameter); template template parameters: `template<template<typename> class Container> class Adapter { ... }` (a template parameter that is itself a template); implement `std::integral_constant<T, V>` pattern which is used pervasively in the STL

## Phase 4: Operator Overloading and RAII (4 items)

- [ ] 4.1 Implement operator overloading: member form `Foo operator+(const Foo& other) const` and free function form `Foo operator+(const Foo& a, const Foo& b)`; overloadable operators: `+ - * / % & | ^ ~ ! << >> == != < > <= >= += -= *= /= %= &= |= ^= <<= >>= [] () -> ->* ++ -- new delete`; `operator[]` returns a reference to enable `vec[0] = 5`; `operator()` enables callable objects (functors); `operator bool` enables `if (ptr)` pattern; resolve binary operators via overload resolution: check member form first, then free function form via ADL
- [ ] 4.2 Implement RAII (Resource Acquisition Is Initialization): at scope exit (normal exit or early `return`), destructors of all local variables are called in reverse order of construction; implement destructor call insertion in the MIR lowering pass — for each block's predecessors, insert cleanup calls for variables that go out of scope; this is the C++ subset's answer to exception handling: no exceptions, no stack unwinding, just deterministic RAII cleanup; destructors of class members are called in reverse field declaration order
- [ ] 4.3 Implement `std::unique_ptr`-style move semantics: move constructor and move assignment operator leave the source in a "valid but unspecified" state (typically null pointer); `std::move(x)` casts `x` to `T&&` (rvalue reference), enabling move construction/assignment instead of copy; implement rvalue reference type `T&&` in the type system; overload resolution prefers `T&&` overloads for temporaries and `std::move` results; move semantics for struct fields in MIR: copy the bits, then null the source fields
- [ ] 4.4 Implement function overloading with overload resolution (C++17 §16.3): when multiple functions have the same name, select the best viable candidate; viability: argument count matches (accounting for default arguments), each argument is implicitly convertible to the parameter type; ranking: exact match > promotion > standard conversion > user-defined conversion; tie-breaking: non-template preferred over template, more specialized template preferred; implement default function arguments `void foo(int x, int y = 0)` — callers may omit trailing arguments

## Phase 5: Standard Library Subset (3 items)

- [ ] 5.1 Implement `<string>` header with `std::string`: stores UTF-8 bytes with SSO (Small String Optimization — inline buffer for strings up to 22 bytes on 64-bit); methods: `c_str()`, `data()`, `size()`, `length()`, `empty()`, `append()`, `push_back()`, `substr()`, `find()`, `operator+`, `operator==`, `operator<`; implement `<sstream>` with `std::ostringstream` (needed by LLVM shim code for error message formatting); implement `<string_view>` (non-owning reference to string data)
- [ ] 5.2 Implement `<vector>` header with `std::vector<T>`: heap-allocated dynamic array with amortized O(1) push_back (growth factor 2x); methods: `push_back()`, `emplace_back()`, `pop_back()`, `size()`, `empty()`, `reserve()`, `resize()`, `clear()`, `begin()`/`end()` iterators, `operator[]`, `at()`, `data()`, `front()`, `back()`; implement `<memory>` with `std::unique_ptr<T>` (move-only, RAII wrapper) and `std::make_unique<T>(args...)` factory function; `std::shared_ptr<T>` is explicitly out of scope for this phase
- [ ] 5.3 Implement C compatibility headers: `<cstdio>` (wraps `stdio.h` — `printf`, `fprintf`, `sprintf`, `snprintf`, `fopen`, `fclose`, `fread`, `fwrite`), `<cstdlib>` (wraps `stdlib.h` — `malloc`, `free`, `exit`, `abort`, `atoi`, `strtol`), `<cstring>` (wraps `string.h` — `memcpy`, `memmove`, `memset`, `memcmp`, `strlen`, `strcpy`, `strcmp`), `<cstdint>` (wraps `stdint.h` — `uint8_t`, `int64_t`, etc.), `<cassert>`, `<cstddef>` (`size_t`, `ptrdiff_t`, `nullptr_t`); all in `namespace std` with `using` declarations for the C names
