# phase26f — Move-Semantics Activation Milestone (the zero-cost enabler)

> The deferred, high-blast-radius core of the memory model (user decision 2026-07-16,
> rulebook decision #12). Activating real move semantics is what makes TML genuinely
> Rust-like/zero-cost — but it makes use-after-move a compile error and breaks every
> implicit-copy site (stdlib included), so it is a conscious milestone taken AFTER the
> concrete bugs are closed (phase26b Step 3). Foundation already in place: exported
> borrow facts (phase26b 2.1-2.3, v0.3.57, def-span join 100%) + accurate `initialized`
> state. Prereq: phase26b Step 3 (sound read-outs) landed, so container copies are the
> only remaining copy-double-free source.

## 1. Implementation
- [x] 1.1 Activate the checker's move dataflow: `move_value` / `move_projection` are now invoked at the real move sites (v0.3.60). **Wired (file:line-kind):** let-init ident + `let leaf = base.field` partial → `checker_stmt.cpp` `check_let`; by-value function args (honours `ref`/`mut ref` params via `TypeEnv::lookup_func`) → `checker_expr.cpp` `check_call`; by-value method args (receiver stays a borrow) → `check_method_call`; struct field inits + `..base` → `check_struct_expr`; enum-payload/constructor args → `check_call` (no free-func sig ⇒ by-value); `return` of a local → `check_return`; `x = y` → `check_binary`. **Prerequisite:** places were `nullptr`-typed (so `is_copy_type`⇒everything copy); type checker now records each `IdentPattern`'s resolved type in `expr_types_` (`types/checker/stmt.cpp` `bind_pattern`) and the checker threads it into places. Move classification = `!is_copy_type`. **Acceptance met:** join-proof (`TML_DROP_FACTS_DEBUG=1`) now shows `var=x moved_out=1 … DISAGREE-payoff` on `let y = x` (was uniformly 0); `refcount_bleed_probe` shows all `moved_out=0` (no false positives, `.duplicate()`/receivers correctly not moved).
- [x] 1.2 Use-after-move policy staged behind `TML_STRICT_MOVES=1` (read once, cached). **Default OFF** = facts populate, zero new diagnostics, zero behaviour change (all move-derived errors gated; `Moved` sticky through `drop_scope_places`; reassignment re-inits). **Flag-OFF regression:** determinism 22/22 adversarial, core/alloc 44/44, core/str 32/32, std/json 23/23, collections 19/19 (pre-existing `arraylist` K001, phase27a). **BLAST RADIUS (flag ON, 176 files): 53 move-errors / 7 files (4.0%)** — categorized in `specs/blast-radius/spec.md`: **~96% (51/53) idiomatic value-type/pointer copies** (`Layout` reused-by-value dominates = 42 errors across 4 alloc files, Rust's Layout is Copy but no derive; `Point`/`Interval` value structs reused; raw pointers `PtrType` not in `is_copy_type`), **only 1 genuine bug** (`double_free_probe` deliberate double-free). - [x] 1.2b Rust-faithful Copy classification — collapse the blast radius + make `moved_out` reliable (v0.3.61). **`is_copy_type` (`borrow/checker_core.cpp`):** (1) raw pointers `*T`/`*mut T` (`PtrType`) are Copy; (2) transparent named-type aliases are resolved (local table → module registry → global library cache, memoised) and classified by underlying type — handles `Ptr = *Unit` reused across allocator calls even when `core::ptr` is not imported; (3) Copy/Drop mutual exclusion enforced — a type with `impl Drop` NEVER classifies as Copy even given a stray `impl Copy`; (4) the existing `type_implements(name, "Copy")` consult now backed by stdlib derives. **Stdlib Copy derives (`@auto(duplicate)` + `impl Copy for T {}`):** `Layout` (core/alloc/layout), `Interval` (std/collections/interval_tree), `Point` (insertvalue test struct) — all trivially-copyable (all-primitive fields, no `Drop`). **Method-arg param-kind = SAFE-FALLBACK:** the checker no longer sets `moved_out` for bare-identifier method args (param-kind is unresolvable without method resolution; under-move is safe, over-move would leak in 1.3).
